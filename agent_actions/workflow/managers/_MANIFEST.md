# Workflow Managers Manifest

## Overview

Tracks workflow artifacts, batching, loops, state, and skip logic used by the runner.

## Modules

| Name | Type | Description | Signals |
|------|------|-------------|---------|
| `batch.py` | Module | Batch helpers that coordinate chunked execution. `BatchLifecycleManager.handle_batch_agent` runs the collect pass once an action's batches are finished, and completes the action only when the registry reads completed and the pass left no finished file unread (`CollectPass.unread`), a file whose batch the provider failed or cancelled reading completed once the pass has marked its records failed; otherwise it returns `in_progress`, so the run pauses as for a batch still out and the next run reads that file. | `llm.batch`, `processing` |
| `loop.py` | Module | `VersionOutputCorrelator` — version output correlation for parallel map-reduce patterns. `prepare_correlated_input` returns the merged input of each file a version source lists, by its path (`[]` for a file every version holds empty), raises `AllVersionsFilteredError` when every version source produced zero records (executor cascade-skips), or `ConfigurationError` on a correlation/storage fault. It stores nothing: the consumer's own target holds its answers, which a re-run carries records from, so the input is handed to its walk instead. A source that vanishes between listing and reading is skipped rather than raised and marks the consumer's record count unknown, since its correlated input is assembled before its own walk begins. It then deletes each stored file of the merge that no version source lists, its input gone, under a file limit and a repair too, since it lists every version file. A failure only warns. | `workflow`, `validation`, `utils` |
| `manifest.py` | Module | Generates workflow manifests consumed by tooling/docs. | `tooling.docs`, `workflow` |
| `output.py` | Module | `ActionOutputManager`: loads upstream outputs and resolves version correlation. Defines the public `AllVersionsFilteredError`; `resolve_correlated_input` returns a version consumer's merged input by file path (None for any other action), delegating to the correlator and propagating its raise. `detect_explicit_version_consumption()` result is lazy-cached per instance. | `output`, `workflow` |
| `skip.py` | Module | Skip logic used when upstream items fail or guard conditions filter them. | `validation`, `workflow` |
| `state.py` | Module | `ActionStatus(str, Enum)` — typed action lifecycle statuses (`PENDING`, `RUNNING`, `BATCH_SUBMITTED`, `CHECKING_BATCH`, `COMPLETED`, `COMPLETED_WITH_FAILURES`, `FAILED`, `SKIPPED`, `INTERRUPTED`). `COMPLETED_STATUSES`, `TERMINAL_STATUSES`, `RETRYABLE_STATUSES` and `MID_PROCESSING_STATUSES` frozensets derived from enum. `ActionStateManager` — manages action execution state persistence and queries. Key methods: `is_failed()`, `is_skipped()`, `is_terminal()`, `is_in_progress()`, `get_pending_actions()`, `get_skipped_actions()`, `is_workflow_done()`, `get_summary()`, `mark_running_as_failed()`, `mark_running_as_interrupted()`. `reopen(names)` puts several actions back to pending in one write, which is how a reset takes an action and everything that reads it together; it also removes the retired `max_records` marker, which `adopt_truncation_marker` leaves in place when it reports a truncation so that nothing between the read and the reopening write can lose it, and the `REPAIRED_BY` stamp `agac retry` writes beside the status of each action it puts back to pending, since a reset makes what that action holds stale. | `workflow`, `state_management` |
