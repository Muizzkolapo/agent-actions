# Gemini Provider Manifest

## Overview

Google Gemini adapter with batch/online clients.

## Modules

| Name | Type | Description | Signals |
|------|------|-------------|---------|
| `batch_client.py` | Module | Batch Gemini client implementation. Its `genai.Client` waits `LLMDefaults.REQUEST_TIMEOUT_SECONDS` (in ms) per request. Maps every `JobState` into `BatchStatus`: queued, pending, running, paused, updating and cancelling are in flight; succeeded and partially succeeded are completed, and the results of either are read; failed and expired are failed. An action's `vendor_params` go into `generation_config`, except the request-level fields (`_REQUEST_LEVEL_FIELDS`), which go beside it. `generation_config` carries `temperature`, `max_output_tokens` (from `max_tokens`), `top_p`, `stop_sequences` and, in JSON mode, `response_mime_type: application/json`, each only when set, never a null; as online, the schema goes in the prompt text, not as a response schema. The line's one text part is the online request's text (`MessageBuilder.build`'s `prompt_body`): the tagged prompt and record, with the schema block and its rule in JSON mode. Output tokens are `candidatesTokenCount` plus `thoughtsTokenCount`. A failed line's `error_status` is its error's `code`. An answer's text is its text parts joined, thoughts left out, as the SDK's `response.text` reads it. A line with none is not a failed line but `_no_answer` (`client.no_answer`), and `_answer_was_cut_off` is `finishReason` `MAX_TOKENS`. A line's `cachedContentTokenCount` is kept on its usage as `prompt_tokens_details.cached_tokens`, so the cached part of the prompt is counted as the online call counts it. | `llm.batch`, `llm.providers` |
| `client.py` | Module | Online Gemini client wrapper with prompt shaping. A transport failure the SDK lets through (`TRANSPORT_ERRORS`, such as `httpx.ConnectError`) is wrapped as `NetworkError`, so it is retried. `VENDOR_PARAMS` takes the fields of `GenerateContentConfig` but `http_options`, joined into the config the request carries. An empty text answer cut off at `MAX_TOKENS` is a `ResponseTruncatedError`. `no_answer` is how a response with no text ends, for this client and the batch client: a blocked prompt is an error naming `blockReason`, a stop other than `STOP` an `empty_response_error` naming it, and an answer the model ended empty is left to `on_empty` (text mode returns `[]`); in JSON mode each is a `_parse_error` record with the same reason. A JSON answer cut off at `MAX_TOKENS` is a parse error (`cut_off_parse_error`), never repaired into a partial object. | `llm.realtime`, `llm.providers` |
