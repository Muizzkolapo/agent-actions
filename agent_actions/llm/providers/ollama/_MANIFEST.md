# Ollama Provider Manifest

## Overview

Local Ollama adapter offering batch/online clients plus failure injection helpers.

## Modules

| Name | Type | Description | Signals |
|------|------|-------------|---------|
| `batch_client.py` | Module | Batch client interfacing with Ollama daemon. Its `Client` waits the action's `request_timeout` per request, passed in by the batch factory; unset or null, `LLMDefaults.REQUEST_TIMEOUT_SECONDS` (600). A task's `messages` are the online request's (`MessageBuilder.build` with the online client's arguments). A task's `vendor_params` ride on its body and join the `chat()` call as online. As online, an unset temperature is not sent, JSON mode with no schema sends `format="json"` on local, and a record's `finish_reason` is the response's `done_reason` (`length` when cut off at the limit). `_parse_json_content` reads a reply with the online client's `read_json_reply`; text that function refuses (a number, `true`) stays text, a parse error in JSON mode. Ollama has no batch API, so the batch is a loop in this process, run at submit time by a thread pool. Its worker count (`_get_max_workers`) is the action's `batch_max_workers` (handed in by the batch factory), else `OLLAMA_BATCH_MAX_WORKERS`, else 1; a value below 1 falls back to 1 and one above 32 is clamped, the warning naming the setting the value came from. `record_concurrency`, the online setting, never sets it. A failed request's line carries the HTTP `status` of a `ResponseError` (`_http_status`, read by `_extract_error_status`), which decides whether a retry resends it. A failure with no status carries `retriable` at the top of its line, outside the `error` dict that becomes the record's error text (`_online_retries`, read by `_extract_retriable` into `BatchResult.retriable`): whether the online client retries it, classified with the online error mapping, so a transport error is resent and any other is failed at once. | `llm.batch`, `llm.providers`, `processing` |
| `client.py` | Module | Online Ollama client for streaming responses. `read_json_reply` is the one reading of a JSON-mode reply's text, called by `_call_ollama_json` and by the batch client: an object, a list of objects, a list holding a non-object as one record under `response`, or None for text that is neither. A refused connection (which the ollama SDK re-raises as a builtin `ConnectionError`) or any other transport failure (`TRANSPORT_ERRORS`) is wrapped as `NetworkError`, so it is retried. The SDK raises an HTTP error answer as `ollama.ResponseError`, which both error mappings classify by its `status_code`: 429 is a `RateLimitError` and 500, 502, 503 and 504 a `NetworkError`, both retried; any other status (a 400, or a 404 for a model the server does not have) is a non-retriable `VendorAPIError`. `_VENDOR_PARAMS` (both clients' `VENDOR_PARAMS`) takes every argument of `Client.chat`; `options` merges into the generation options. An empty text answer whose `done_reason` is `length` is a `ResponseTruncatedError`. A JSON answer cut off at `done_reason: length` is a parse error naming it (`cut_off_parse_error`), never repaired into a partial object. | `llm.realtime`, `llm.providers` |
| `failure_injection.py` | Module | Simulates failures/latency for Ollama tests. | `tests`, `llm.providers` |
