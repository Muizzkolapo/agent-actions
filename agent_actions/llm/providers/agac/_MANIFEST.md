# AGAC Provider Manifest

## Overview

Claude-branded provider adapter (AGAC) with non-blocking clients and test helpers.

## Project Surface

| Symbol | File | Interaction | Config Key |
|--------|------|-------------|------------|
| `AgacBatchClient._write_state()` | `.agac/batch_state/{batch_id}.json` | Writes | — |
| `AgacBatchClient._load_state()` | `.agac/batch_state/{batch_id}.json` | Reads | — |
| `AgacBatchClient.release_batch()` | `.agac/batch_state/{batch_id}.json` | Deletes | — |
| `AgacBatchClient.discard_partial_writes()` | `.agac/batch_state/*.tmp` | Deletes | — |
| `AgacBatchClient.reset()` | `.agac/batch_state/`, `.agac/batch_attempts.json` | Deletes | — |
| `AgacBatchClient._count_submissions()` | `.agac/batch_attempts.json` | Reads and writes (at each submit) | — |
| `scenario.load` | `sandbox.yml`, or the file `--scenario` names | Reads (once per workflow load of `agac run --sandbox` or `agac retry --sandbox`) | — |
| `rules_for` | `agent_config/{workflow}.yml`, `schema/{workflow}/{action}.yml` | Reads (through the expectation suite the run resolves, once per action in a run) | `actions[].expect` |
| `observed_refs` | `agent_config/{workflow}.yml` | Reads (less a loop's `feedback` inputs) | `actions[].context_scope.observe`, `- loop:` `feedback` |
| `Contract._report` | `agent_io/logs/` | Writes (one warning per run, action and field) | — |

## Modules

| Name | Type | Description | Signals |
|------|------|-------------|---------|
| `batch_client.py` | Module | Offline batch client for testing batch without a vendor. It reads result lines with `OpenAICompatibleResponseMixin` (`_vendor_label` `agac-provider`), as the OpenAI batch client does, except that a line's top-level `error` reads as its `message`. A batch completes at its first status check unless the sandbox scenario's `batch` block sets `polls_until_complete` or `complete_after_seconds` (the constructor's arguments win). At submit `_count_submissions` stamps each task with its record's submission count for its action (`attempt`), kept in `.agac/batch_attempts.json` under a lock (entries older than seven days are dropped), so a retry or repair batch that a later run submits counts on; a task never submitted counts in memory per `custom_id`. A batch holding a task of an action the scenario's `batch.fail` names is recorded `failed` and every status check reports it so. `prepare_tasks` stamps each task with its record's `source_guid` (`record`, read from the row's `RECORD_GUID_KEY`). At collect, under a sandbox scenario, a task with a `record` is left out when `drops` holds (counted `dropped`), becomes `faults.batch_line` for the kind `error_for` picks (counted `errors`), or else has its answer passed through `Contract.follow`; a judge's task gets a passing or failing offered shape by `judge_passes`. `prepare_tasks` adds the action's `Contract.to_task()` to each task, so collecting answers each one with the same rules as online. At submit, `_shared_contracts` keeps each distinct rule set once in the batch record (`contracts`, by key) and each task holds only its key; a task with no rules (or a record with no `contracts`) is answered by the plain generator. Imports `contract` inside the methods that use it. Records a submitted batch under `.agac/batch_state/` in the project so the run that collects it — a separate process, because submitting pauses and asks to be run again — can find it. Answers each task from the schema and prompt that task carries. A task's `model_config` holds only the settings the action sets, never a null. The record outlives the read: collecting hands bytes to a caller that has yet to write and evaluate them, and a re-run must find the same batch. It dies with the registry entry that names it. A batch with no readable record is reported `unknown` and taken as failed: nothing will come back for it. A task whose user message ends by offering answer shapes, as a side call's request may (a judge's does), is answered with one of them, seeded by that message; nothing in it names a kind of side call. | `llm.batch`, `llm.providers` |
| `contract.py` | Module | What a mock answer must meet beyond its schema. `Contract.follow(scenario, rules, record, schema, record_id, attempt)` applies a sandbox scenario to an honest record: when `breaks` holds, `break_rules` makes rules fail (`all`: the one `pick_rule` chooses among the error-severity rules the mock can check; a list: every such rule of those types), trying values led by the rule's own params (a pattern's match, its phrases or values, a word or item count past a bound) in each field the rule reads (every declared field for a record rule) until the real check (`run_suite` over that rule) fails, a value the field's schema accepts first; a rule it cannot break, or a type the action does not check, is logged once per run, action and rule. Then `pin` sets each pinned field and logs once per run, action and field a value its schema or a rule refuses; the value is kept. `Contract.for_request` reads the action's rules with `rules_for`, through the same suite resolution the run uses (`create_expectation_service_from_config`), less `llm_judge` rules and unregistered types, cached per run on the action and a hash of its `expect`, schema, schema name and project root; the record's context as the request sends it; and the action's `context_scope.observe`. `Contract.generate` builds each top-level field a rule names to meet its schema and rules (`enum` ∩ `accepted_values`, `matches_regex` and schema `pattern` through `regex_gen` on a string or untyped field, the number a pattern spells on an `integer`/`number` field, else a value of the field's type; a negated pattern, `word_count_between`, `item_count`, `not_null`/`no_null_fields`, `field[*]` element rules), checks each field with the real registered check, then checks the whole record with the real `run_suite` and builds it again up to `TRIES` (20) times. A rule no record can meet (`_unmeetable`: a pattern Python cannot compile, or a field the schema does not declare) gets no tries and adds no key. An output field that an observe reference names exactly (`ns.field`, never `ns.*`, never a loop's `feedback` input, which holds the previous iteration) copies that input when it meets the field's schema and rules. What still fails is logged once per run, action and field, naming the constraints; a run is `run_key`: the `workflow_session_id` and the event `correlation_id` each run sets at start (`reset_runs` forgets all runs; at most `_MAX_RUNS` are kept). The best attempt is returned, ranked first by fields the schema refuses, then by failed rules. `to_task`/`from_task` carry the rules, observe list and session id on a batch task; the task's `user_content` is the context. With no rules, the answer is the plain generator's, plus any copied inputs. | `llm.providers`, `expectations` |
| `scenario.py` | Module | The sandbox scenario. `load(source, project_root, llm_actions)` reads a preset (`PRESETS`: `happy`, no faults; `chaos`, `seed: 0`, errors at 0.1 of `rate_limit`/`timeout`/`truncated`/`empty` healed at attempt 2, one rule broken at 0.2 healed at attempt 2, judge `pass_rate` 0.7, batch `polls_until_complete: 1` and `drop_rate: 0.1`), the file a path names, or with no source `SCENARIO_FILE` (`sandbox.yml`) at the project root, else `happy`. Pydantic models with `extra="forbid"` refuse an unknown key; a rate outside [0, 1], a `heal_on_attempt` below 2, an unknown error kind (`ERROR_KINDS`), a `latency_ms` range with min above max, an action name that names no LLM action of the workflow nor the base of a version group (`vote` for `vote_1`), and a `break_rules.rules` type the expectation registry does not know are refused too: one `ConfigurationError` naming the file and each key. `Scenario.rules_for(action, context)` merges, each key whole, a `records` entry whose `match` (dotted paths into the context as the request sends it) the context meets and that names the action (`error: <kind>` is errors at rate 1 of that kind), over `actions.<name>` (or the version group's base), over `defaults`. Each decision (`error_for`, `breaks`, `pick_rule`, `latency_ms`, `judge_passes`, `drops`) is `chance(action, record, attempt, decision)`: a SHA-256 of the seed and those values mapped to [0, 1), so no call order changes it. `drops` holds for a record's first submission only. `count`/`summary` keep the run's `errors`, `rules_broken` and `dropped` counts, thread-safe, for the line the CLI prints. | `config.sandbox`, `llm.providers` |
| `faults.py` | Module | Each scenario fault as a real OpenAI-style vendor shows it. Online: `rate_limit` and `server_error` (an `httpx.HTTPStatusError` of 429 or 503) and `timeout` (`httpx.ReadTimeout`) are raised through `error_wrapper.wrap_vendor_error` as `RateLimitError` / `NetworkError`, which the retry policy retries; in JSON mode (`json_answer`) a `refusal` and an `empty` answer are the `_parse_error` records `chat_no_answer` names, `truncated` is the first half of the honest answer with `cut_off_parse_error("length")`, and `invalid_json` is `unparsed_json_record` of text with no brace; in text mode (`text_answer`) `refusal` and `empty` raise `VendorAPIError` and `truncated` raises `ResponseTruncatedError`, each from `chat_no_answer`, and `invalid_json` returns that text. `batch_line` turns an honest result line into a 429/503 line with an error body, a line with a top-level `error` for a timeout, or a 200 line whose message holds a refusal, no content, cut-off content with `finish_reason: length`, or that text. | `llm.providers` |
| `regex_gen.py` | Module | `generate(pattern, rng)` builds a string from a bounded regex subset: literals and escapes, `.`, `\d \w \s` and negations, `[...]` with ranges and negation, `? * + {m} {m,} {m,n} {,n}` (an unbounded repeat adds at most `UNBOUNDED_EXTRA`, 3), groups `( )`, `(?: )`, `(?P<name> )`, `|`, `^ $`. Anything else raises `UnsupportedPattern`, as does a pattern `re.compile` refuses, one nested too deep (`RecursionError`), or a braced repeat count above `MAX_REPEAT` (1000). Each pattern's parse is cached. Written by hand, not on `re._parser`, which is private. The caller checks each result with `re`. | `llm.providers` |
| `client.py` | Module | Online client for Claude Code/AGAC interactions. Under a sandbox scenario (`config.sandbox.scenario()`), a call naming a record (`RECORD_GUID_KEY`, else `RECORD_ID_KEY`) first sleeps its `latency_ms`, then answers the fault `error_for` picks as `faults` shows it (counted `errors`), or else passes its honest answer through `Contract.follow`; a call naming no record (a judge's side call) gets a passing or failing offered shape by `judge_passes`. In JSON mode the answer comes from `Contract.for_request(...).generate`; `contract` is imported there, not at module level, because the online client registry loads this module for every vendor. In text mode (`json_mode: false`) a prompt whose last non-empty line is only two or more JSON objects joined by ` or ` gets one of those objects back (seeded choice, string values replaced by generated sentences); that is how an `llm_judge` gets a verdict. Any other text prompt gets prose. `VENDOR_PARAMS` accepts any key and reads none, so a workflow switched to it keeps its `vendor_params`. The attempt it answers with is counted per action and record: the record is the `_record_id` on the call's config (`RECORD_ID_KEY`, set by `run_dynamic_agent`), else a `source_guid` in the context, else one counter for the action (a side call, such as a judge's). The counts are kept per run (`contract.next_attempt`, under the same `run_key` as the unmet-constraint warnings), so each run starts each record at attempt 1. The batch client counts per action and `custom_id`, which is per record, stamped on each task at submit. | `llm.realtime`, `llm.providers` |
| `fake_data.py` | Module | Test helpers that simulate Claude responses. `offered_answer_shapes` reads the answer shapes a prompt's last line offers; `generate_offered_answer` returns one of them, with `passing` set one whose `passed` is that value when one is. A string schema with a `pattern` is built by `from_pattern` (through `regex_gen`, kept only when `re.search` matches and it fits the length bound; None on an unsupported pattern, `re.error` or `RecursionError`), else as before. `sentence_of(n, rng)` is a sentence of exactly n words. `generate_openai_response` takes an optional `contract` that builds the record. A declared `minimum`/`maximum` (or `exclusiveMinimum`/`exclusiveMaximum`) wins over the field-name rules: the value is drawn uniformly inside the bound, on a `multipleOf` step when one is declared (a whole-number step for an integer); a one-sided bound is completed from 0 or 1000 away; name rules apply only to an unbounded field. A string outside its `minLength`/`maxLength` is padded with sentences or cut at a word boundary, a field-name value such as an email included; one of `KNOWN_FORMATS` keeps its format. | `tests`, `llm.providers` |

## Dependencies

| Package | Direction | Why |
|---------|-----------|-----|
| `expectations` | outbound | `contract.py` resolves the action's suite with `create_expectation_service_from_config`, runs single checks from `registry`, and checks the whole record with `runner.run_suite` |
| `utils` | outbound | `contract.py` checks a value against its field schema with `jsonschema_cache.checked_validator` |
| `logging` | outbound | `contract.run_key` reads the run's event `correlation_id` from `logging.core.manager` |
| `config` | outbound | `client.py` and `batch_client.py` read the loaded scenario with `config.sandbox.scenario()` |
| `config` | inbound | `config.sandbox.load_scenario` calls `scenario.load` |
| `errors` | outbound | `scenario.load` raises `ConfigurationError`; `faults` raises the errors `error_wrapper` builds |
