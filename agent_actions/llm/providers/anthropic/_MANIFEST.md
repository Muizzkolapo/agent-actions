# Anthropic Provider Manifest

## Overview

Anthropic-specific batch and online clients plus the thin adapter glue.

## Modules

| Name | Type | Description | Signals |
|------|------|-------------|---------|
| `batch_client.py` | Module | Batch client implementing Anthropic's API. A batch `canceling` is in flight; `ended` is completed, a canceled batch included. A status poll the server cannot answer now (a connection failure, `InternalServerError`, or one of `server_busy_errors`) is a transient error, asked again on the next run. Each line takes the action's `vendor_params`. In JSON mode the compiled schema is the line's `tools`, unchanged, as the online request sends it: offered, not forced (forced, a nested array of objects came back as one JSON string); `vendor_params.tool_choice` forces it where a workflow wants that. A succeeded result whose blocks hold no text or tool_use answer (a thinking block alone, as when thinking spent `max_tokens`) is an answer with no content (`_no_answer`, from `client.no_answer`), never content: in text mode it fails with the `empty_response_error` message that online raises, resent by a retry only when cut off; a message of no blocks, or of empty text, that the model ended itself is left to `on_empty`; in JSON mode each is the parse error online stores (`no_tool_answer_message`). A text answer cut off at the output limit or stopped by the provider (`_answer_was_cut_off` reads `is_unfinished`: `max_tokens`, `refusal`) is returned as written, not parsed: json_repair would complete the half JSON; a tool answer is returned as online returns it. Each line's `messages` are the online request's (`MessageBuilder.build` with the online client's arguments): one tagged user message holding the prompt and the record, and no `system`; a prompt too large for the model is refused as online refuses it. With `enable_prompt_caching`, the prompt part of that message carries `cache_control: {type: ephemeral}` by the online marking rule when `prompt_is_shared` holds for the call (`_caches_prompt`), and the record part is always sent unmarked; a repair row's feedback follows the marked prompt in the unmarked block (`BatchTask.shared_prompt_len`), and the batch is created with the prompt-caching `anthropic-beta` header; no line carries `extra_headers`. An errored result's `error_status` is the HTTP status of its error type (`_ERROR_TYPE_STATUS`: `invalid_request_error` 400, `rate_limit_error` 429, `overloaded_error` 529, ...); an expired or canceled one has none, so a retry resends it. `_answer_text` gives a text reply's text, which content extraction has already parsed. A text reply is read with the online client's `json_answer_in`: an object or a non-empty list of objects is the answer, and any other text (a list holding a string, a number, `null`, prose) stays text, a parse error in JSON mode, as online refuses it. A JSON action with no schema is sent no tool, as online. A cut-off text answer's `parse_error` is online's (`_cut_off_parse_error`). | `llm.batch`, `llm.providers` |
| `__init__.py` | Module | `PROMPT_CACHING_BETA_HEADER`, and `server_busy_errors(anthropic)`: the SDK's errors for a server that cannot answer now that are not `InternalServerError` (`OverloadedError` for 529, and `ServiceUnavailableError`/`DeadlineExceededError` for 503/504 on platforms that raise them), as far as the installed SDK defines them. | `llm.providers` |
| `client.py` | Module | Online Anthropic client for streaming responses. A 429 is a `RateLimitError`; a connection failure, an `InternalServerError` (5xx) or one of `server_busy_errors` (529 overloaded included) is a `NetworkError`; both are retried. `VENDOR_PARAMS` takes every keyword of `messages.create` (`extra_headers`/`extra_body`/`extra_query` merge). In JSON mode the request offers the schema tool without forcing it: forced, claude-haiku-5-5 returned a nested array as one JSON string (#1781); `vendor_params.tool_choice` forces it where a workflow wants that. `vendor_params_conflicts(agent_config)` names what the API refuses beside `vendor_params.thinking` (type not `disabled`), for preflight: a temperature other than 1, a top_p below 0.95, any top_k, a forced tool_choice, and with `type: enabled` a `budget_tokens` at or above the effective `max_tokens` (default 4096) unless `extra_headers` sends the interleaved-thinking beta; each setting is read from `vendor_params`, then its `extra_body`, then the action. A request key the installed SDK's `create` does not take (`temperature`, `top_p` on anthropic 1.x) moves to `extra_body` (`VendorParamSpec.fit`), so it reaches the API rather than raising in the SDK. In JSON mode a finished text answer (no tool block, stop reason not a cut-off) is read with `parse_llm_json`, fenced or bare; only text that is not JSON returns the `_parse_error` sentinel. A `max_tokens` the SDK would refuse unstreamed (`_needs_streaming`: above 21,333, or the model's lower limit) goes through `messages.stream` and `get_final_message`. A message with no text raises `empty_response_error` with the stop reason; one of no blocks, or of empty text, that the model ended itself (`_OWN_STOP_REASONS`) is returned as `[]`, the empty answer `on_empty` decides. `no_answer` decides both, for this client and the batch client; `no_tool_answer_message` is the JSON-mode parse error of both. With `enable_prompt_caching`, the request is marked only when `prompt_is_shared` holds; a repair call's `_shared_prompt_len` goes to `MessageBuilder.build` as `shared_prompt_len`, so its feedback follows the marked prompt unmarked. At import it builds the models of `Message`, `RawMessageStreamEvent` and the stream helper's events (`MessageStreamEvent`, and `ParsedMessageStreamEvent` where the SDK has it) with `build_sdk_models`, which the SDK may otherwise build on first parse, in several record threads at once. `json_answer_in` is the JSON answer a text reply holds, an object or a non-empty list of objects; `call_json` and the batch client both read a text reply with it. | `llm.realtime`, `llm.providers` |
