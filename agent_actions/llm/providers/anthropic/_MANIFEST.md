# Anthropic Provider Manifest

## Overview

Anthropic-specific batch and online clients plus the thin adapter glue.

## Modules

| Name | Type | Description | Signals |
|------|------|-------------|---------|
| `batch_client.py` | Module | Batch client implementing Anthropic's API. A batch `canceling` is in flight; `ended` is completed, a canceled batch included. A status poll the server cannot answer now (a connection failure, `InternalServerError`, or one of `server_busy_errors`) is a transient error, asked again on the next run. Each line takes the action's `vendor_params`. In JSON mode the compiled schema is the line's `tools`, unchanged, as the online request sends it: offered, not forced (forced, a nested array of objects came back as one JSON string); `vendor_params.tool_choice` forces it where a workflow wants that. With `enable_prompt_caching`, the system prompt carries `cache_control: {type: ephemeral}` by the online marking rule when `prompt_is_shared` holds for the call (`_caches_prompt`), and the record's message is always sent unmarked; a repair row's feedback follows the marked prompt as its own unmarked system block (`BatchTask.shared_prompt_len`), and the batch is created with the prompt-caching `anthropic-beta` header; no line carries `extra_headers`. | `llm.batch`, `llm.providers` |
| `__init__.py` | Module | `PROMPT_CACHING_BETA_HEADER`, and `server_busy_errors(anthropic)`: the SDK's errors for a server that cannot answer now that are not `InternalServerError` (`OverloadedError` for 529, and `ServiceUnavailableError`/`DeadlineExceededError` for 503/504 on platforms that raise them), as far as the installed SDK defines them. | `llm.providers` |
| `client.py` | Module | Online Anthropic client for streaming responses. A 429 is a `RateLimitError`; a connection failure, an `InternalServerError` (5xx) or one of `server_busy_errors` (529 overloaded included) is a `NetworkError`; both are retried. `VENDOR_PARAMS` takes every keyword of `messages.create` (`extra_headers`/`extra_body`/`extra_query` merge). In JSON mode the request offers the schema tool without forcing it: forced, claude-haiku-5-5 returned a nested array as one JSON string (#1781); `vendor_params.tool_choice` forces it where a workflow wants that. A request key the installed SDK's `create` does not take (`temperature`, `top_p` on anthropic 1.x) moves to `extra_body` (`VendorParamSpec.fit`), so it reaches the API rather than raising in the SDK. In JSON mode a finished text answer (no tool block, stop reason not a cut-off) is read with `parse_llm_json`, fenced or bare; only text that is not JSON returns the `_parse_error` sentinel. A `max_tokens` the SDK would refuse unstreamed (`_needs_streaming`: above 21,333, or the model's lower limit) goes through `messages.stream` and `get_final_message`. An empty text answer raises `empty_response_error` with the stop reason. With `enable_prompt_caching`, the request is marked only when `prompt_is_shared` holds; a repair call's `_shared_prompt_len` goes to `MessageBuilder.build` as `shared_prompt_len`, so its feedback follows the marked prompt unmarked. At import it builds the models of `Message`, `RawMessageStreamEvent` and the stream helper's events (`MessageStreamEvent`, and `ParsedMessageStreamEvent` where the SDK has it) with `build_sdk_models`, which the SDK may otherwise build on first parse, in several record threads at once. | `llm.realtime`, `llm.providers` |
