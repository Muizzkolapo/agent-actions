# LLM Providers Manifest

## Overview

Provider adapters expose batch/online clients, failure injection helpers, and
shared utilities (mixins, usage tracking) for each supported LLM vendor.

## Modules

| Name | Type | Description | Signals |
|------|------|-------------|---------|
| `batch_base.py` | Module | Base helpers shared by batch clients (request shaping, telemetry). `prepare_tasks` encodes each record's content into the task's `user_content` with `deep_json`, so a record's depth does not limit the request. A row carrying its own `compiled_schema` is formatted with it in place of the action's. Each task's `model_config` carries the action's `vendor_params`, which each client's `format_task_for_provider` joins into the batch line (`VendorParamSpec.apply_to_body`; Gemini splits them between `generation_config` and the request, Ollama keeps them on the body for its local `chat()` call). `check_status` raises each client's `_transient_errors` (its SDK's connection, timeout and server errors) as `ConnectionError`, which every status poll and the collect pass take as "ask again on the next run". `submit_batch` and `check_status` both return a `BatchStatus` value, the only kind the batch registry acts on: each client's `_normalize_status` maps its SDK's whole status type (in flight while queued, paused or being cancelled; `failed` once expired), and `_known_status` takes one no mapping knows as `in_progress`, warning with the batch and the status, so the provider is asked about it again. | `llm.batch` |
| `batch_client_factory.py` | Module | Factory that returns a provider-specific batch client implementation. | `llm.batch`, `llm.providers` |
| `client_base.py` | Module | Abstract base client that defines the interface for streaming/call semantics. Caches SDK clients by class, API key and constructor kwargs such as `base_url` and `default_headers` (mappings are frozen into the key). `BaseClient.VENDOR_PARAMS` is each client's `VendorParamSpec`: the `vendor_params` keys its request takes (`None` on tool and hitl, which send none). | `llm.providers`, `llm.realtime` |
| `error_wrapper.py` | Module | Unified vendor error wrapping: maps SDK exceptions to RateLimitError/NetworkError/VendorAPIError. `_extract_retry_after` reads `retry-after-ms`, then `retry-after` as seconds or as an HTTP date (a wait in the past is 0) into the `RateLimitError` context's `retry_after`. `TRANSPORT_ERRORS` (builtin `ConnectionError` and `TimeoutError`, httpx's network, timeout and remote-protocol errors) is the request that never got an answer: every online client catches it and every mapping wraps it as `NetworkError`, so the retry service retries it, since the ollama SDK re-raises a refused connection as a builtin `ConnectionError` and the gemini and cohere SDKs let httpx's errors through. The SDK's text is masked by value (`register_secret`) and key shape before it becomes a message or an event, so a server body that echoes a credential reaches no record reason. `empty_response_error` builds the error for a response with no answer, naming the vendor's stop reason (`stop_reason_name`, an enum by its value); a stop at the output limit (`is_truncated`: `max_tokens` or `length`, any case) is a retriable `ResponseTruncatedError`, any other a `VendorAPIError`. | `errors`, `llm.providers` |
| `failure_injection.py` | Module | Utility to simulate latency/failure scenarios across providers. | `logging`, `llm.providers` |
| `generation_params.py` | Module | Shared helper (`extract_generation_params`) for extracting temperature/max_tokens/top_p/stop from agent config with vendor-specific key mapping. `request_timeout_seconds` gives an action's `request_timeout`, or `LLMDefaults.REQUEST_TIMEOUT_SECONDS` (600) when it is unset or null, so no SDK waits forever; `request_timeout_kwargs` gives it as the SDK `timeout` kwarg (ollama, cohere); `connect_limited_timeout_kwargs` gives it as an `httpx.Timeout` with `LLMDefaults.CONNECT_TIMEOUT_SECONDS` (5) to connect (openai, llamafile, endpoints, anthropic, groq), the connect limit those SDKs keep by default. Gemini converts it to `http_options.timeout` in ms itself. A declared endpoint sends only an action's own value and otherwise keeps its `timeout_seconds`. `GENERATION_PARAMS` includes `vendor_params`, so an edit to it counts in the generation hash. `VendorParamSpec` is one vendor's pass-through: `accepted` (the SDK request's keywords, from `sdk_keyword_params`, or `None` for any key), `reserved` (`ALWAYS_RESERVED`: model, messages, tools, system, stream, timeout, plus the vendor's own), and `merged` (dict keys joined into agac's dict rather than replacing it). `defects` lists the keys preflight refuses, `apply` joins an action's `vendor_params` into an online request, `apply_to_body` into a batch line. | `llm.providers` |
| `local_batch_records.py` | Module | Reclaiming what a provider recorded in the project about a batch the registry no longer names. Only the agac provider records one; every other keeps its copy at the vendor. | `llm.batch`, `llm.providers` |
| `mixins.py` | Module | Shared mixins for access token handling, logging, context propagation. | `llm.providers` |
| `usage_tracker.py` | Module | Central usage tracking and quota summary used by providers. | `logging`, `llm.providers` |
| `agac/__init__.py` | Module | `agac` (Claude-branded) provider helpers (callbacks, config). | `llm.providers` |
| `anthropic/__init__.py` | Module | Anthropic-specific client wrappers and guardrails. | `llm.providers`, `anthropic` |
| `cohere/__init__.py` | Module | Cohere provider adapter for embeddings/inference. | `llm.providers`, `cohere` |
| `gemini/__init__.py` | Module | Gemini provider wiring (Google Gemini). | `llm.providers`, `google` |
| `groq/__init__.py` | Module | Groq provider binding for Groq Cloud inference. | `llm.providers`, `groq` |

| `ollama/__init__.py` | Module | Ollama provider with dual registration: `ollama_local` (no auth, `OLLAMA_HOST`, API-enforced structured output via `format` param) and `ollama_cloud` (Bearer auth via `OLLAMA_API_KEY`, `OLLAMA_CLOUD_HOST`, no structured output support yet). | `llm.providers`, `ollama` |
| `openai/__init__.py` | Module | OpenAI provider adapter with tool/window shaping. | `llm.providers`, `openai` |
| `tools/__init__.py` | Module | Tool discovery/registration for OpenAI function calling formats. | `llm.providers`, `tools` |
| `hitl/__init__.py` | Module | Human-in-the-loop provider for synchronous approval/rejection workflows. | `llm.providers`, `hitl` |
