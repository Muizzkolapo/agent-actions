# LLM Providers Manifest

## Overview

Provider adapters expose batch/online clients, failure injection helpers, and
shared utilities (mixins, usage tracking) for each supported LLM vendor.

## Modules

| Name | Type | Description | Signals |
|------|------|-------------|---------|
| `batch_base.py` | Module | Base helpers shared by batch clients (request shaping, telemetry). A row carrying its own `compiled_schema` is formatted with it in place of the action's. A task's `temperature` is the action's, or None when the action sets none; no client sends a None, so an unset temperature is left to the model, as online. Each task's `model_config` carries the action's `json_mode` (so a client can ask for JSON when no schema is set, as online does) and its `vendor_params`, which each client's `format_task_for_provider` joins into the batch line (`VendorParamSpec.apply_to_body`; Gemini splits them between `generation_config` and the request, Ollama keeps them on the body for its local `chat()` call). It also carries the action's `top_p`, `stop`, `frequency_penalty` and `presence_penalty` when set; each client sends them through `_sampling_params` (`extract_generation_params` over those keys) with its online client's key map: OpenAI and Groq all four, Anthropic and Gemini (`generation_config`) `top_p` and `stop_sequences`, Ollama `top_p` and `stop` in `options`. `check_status` raises each client's `_transient_errors` (its SDK's connection, timeout and server errors) as `ConnectionError`, which every status poll and the collect pass take as "ask again on the next run". `submit_batch` and `check_status` both return a `BatchStatus` value, the only kind the batch registry acts on: each client's `_normalize_status` maps its SDK's whole status type (in flight while queued, paused or being cancelled; `failed` once expired), and `_known_status` takes one no mapping knows as `in_progress`, warning with the batch and the status, so the provider is asked about it again. `prepare_tasks` asks `_caches_prompt` once per call and sets `BatchTask.cache_prompt` on every task; the base answers no, and the Anthropic client answers `enable_prompt_caching` and `prompt_is_shared`. A repair row's `_shared_prompt_len` (`cache_scope.SHARED_PROMPT_LEN_KEY`) moves to `BatchTask.shared_prompt_len`: how much of `prompt` every record shares. Only the Anthropic client reads it; every other client sends `prompt` as it is. A repair row's `_request_varies_per_record` (`cache_scope.REQUEST_VARIES_PER_RECORD_KEY`: its prompt does not begin with the action's) turns `cache_prompt` off for that task, as the online repair call's config does. A failed line's `BatchResult` carries `error_status`, the HTTP status its request was answered with, from each client's `_extract_error_status` (None, the base answer, when the line does not say), and `retriable` where the client knows the error online raises for it: a failed line's `_extract_retriable` (None, the base answer, leaves the status to decide), and a line with no answer in it, whose `retriable` is `NoAnswer.retried`. `parse_provider_response` parses a string answer as JSON unless `_answer_was_cut_off` (base: never; each client reads its vendor's finish reason through `is_truncated`) says the output limit stopped it: that text stays as written and the result's `parse_error` names the stop reason (`_cut_off_parse_error`), as online refuses to read a cut-off answer. A line the provider answered with no answer in it (`_no_answer`: a refusal, a blocked prompt, no text) is a successful result with no content that keeps its tokens and metadata: `parse_error` holds what online's JSON-mode call stores and `error` what its text-mode call raises, None where the empty answer is left to `on_empty`. `llm.batch.services.shared.settle_unanswered` turns either into content once the action's mode is known. `BatchResult.text` keeps a reply as the model wrote it before the lenient JSON parse (`_answer_text` for a client whose extraction already parsed it); it is not persisted between passes. `prepare_tasks` encodes each record's content into the task's `user_content` with `ContextService.prepare_context_data`, the function the online call uses (`ensure_json_safe`, then `deep_json` with `ensure_ascii=False`), so both modes send the same text and a record's depth does not limit the request. Each client's `format_task_for_provider` builds its messages with `MessageBuilder.build` and the arguments its online client passes (`BatchTask.json_mode` says whether the online twin is a JSON-mode call), so a batch line asks the model what the online request asks. A row whose prompt `build` refuses as too large for the model (`PromptTooLargeError`) gets no task: the error is left on the row under `UNSENT_ERROR_KEY`, and the caller fails that record alone (the batch preparator) or raises it (`raise_unsent`: a judge batch, `BatchStrategy.flush`). A client reads a reply the way its online client does in JSON mode by overriding `_parse_json_content` (Anthropic, Ollama); the base keeps a reply that is one JSON string as written, quotes included. The action's mode is not known here: for a text-mode action the collect pass puts the text back (`llm.batch.services.shared`). A judge request's row carries the judge prompt as its `prompt` and an empty string as its `content`, as the online judge call passes them. | `llm.batch` |
| `batch_client_factory.py` | Module | Factory that returns a provider-specific batch client implementation. | `llm.batch`, `llm.providers` |
| `client_base.py` | Module | Abstract base client that defines the interface for streaming/call semantics. Caches SDK clients by class, API key and constructor kwargs such as `base_url` and `default_headers` (mappings are frozen into the key). `BaseClient.VENDOR_PARAMS` is each client's `VendorParamSpec`: the `vendor_params` keys its request takes (`None` on tool and hitl, which send none). `get_api_key` raises `ConfigurationError` for a missing key, an unset variable or an empty variable; it names the action as `action_name` and leaves `agent`, the workflow, to the caller. | `llm.providers`, `llm.realtime` |
| `error_wrapper.py` | Module | Unified vendor error wrapping: maps SDK exceptions to RateLimitError/NetworkError/VendorAPIError. `_extract_retry_after` reads `retry-after-ms`, then `retry-after` as seconds or as an HTTP date (a wait in the past is 0) into the `RateLimitError` context's `retry_after`. `TRANSPORT_ERRORS` (builtin `ConnectionError` and `TimeoutError`, httpx's network, timeout and remote-protocol errors) is the request that never got an answer: every online client catches it and every mapping wraps it as `NetworkError`, so the retry service retries it, since the ollama SDK re-raises a refused connection as a builtin `ConnectionError` and the gemini and cohere SDKs let httpx's errors through. The SDK's text is masked by value (`register_secret`) and key shape before it becomes a message or an event, so a server body that echoes a credential reaches no record reason. `empty_response_error` builds the error for a response with no answer, naming the vendor's stop reason (`stop_reason_name`, an enum by its value); a stop at the output limit (`is_truncated`: `max_tokens` or `length`, any case) is a retriable `ResponseTruncatedError`, any other a `VendorAPIError`. `refusal_text` is the message for an answer the model declined, quoting its reason. `chat_no_answer` is how a chat-completions message with no answer ends (no content, or content the output limit stopped at an empty string; a refusal ends with the model's reason): the OpenAI and Groq online clients and `OpenAICompatibleResponseMixin` all end such a message with it. `error_for_status` gives the error online raises for a bare HTTP status, for the batch retry, which has no exception: 429 a `RateLimitError`, any 5xx a `NetworkError`, any other a `VendorAPIError`. `NoAnswer` is how a response with no answer ends in each mode: the `_parse_error` a JSON-mode call stores, and the error a text-mode call raises (None: left to `on_empty`); `retried` is whether the retry policy retries that error. `empty_parse_error` and `cut_off_parse_error` are the parse errors of a JSON-mode response with no text and of a JSON answer the output limit stopped, each naming the stop reason. | `errors`, `llm.providers` |
| `failure_injection.py` | Module | Utility to simulate latency/failure scenarios across providers. | `logging`, `llm.providers` |
| `generation_params.py` | Module | Shared helper (`extract_generation_params`) for extracting temperature/max_tokens/top_p/stop from agent config with vendor-specific key mapping. `request_timeout_seconds` gives an action's `request_timeout`, or `LLMDefaults.REQUEST_TIMEOUT_SECONDS` (600) when it is unset or null, so no SDK waits forever; `request_timeout_kwargs` gives it as the SDK `timeout` kwarg (ollama, cohere); `connect_limited_timeout_kwargs` gives it as a `Timeout` with `LLMDefaults.CONNECT_TIMEOUT_SECONDS` (5) to connect (openai, llamafile, endpoints, anthropic, groq), the connect limit those SDKs keep by default. The caller passes its SDK module and the timeout is built with that SDK's own `Timeout` class, because an SDK on httpx2 (anthropic 1.x, openai 3.x) refuses an `httpx.Timeout`. Gemini converts it to `http_options.timeout` in ms itself. A declared endpoint sends only an action's own value and otherwise keeps its `timeout_seconds`. `GENERATION_PARAMS` includes `vendor_params`, so an edit to it counts in the generation hash. `VendorParamSpec` is one vendor's pass-through: `accepted` (the SDK request's keywords, from `sdk_keyword_params`, or `None` for any key), `reserved` (`ALWAYS_RESERVED`: model, messages, tools, system, stream, timeout, plus the vendor's own), and `merged` (dict keys joined into agac's dict rather than replacing it). `defects` lists the keys preflight refuses, `apply` joins an action's `vendor_params` into an online request, `apply_to_body` into a batch line, and `fit` moves a key agac built that the installed SDK's request does not take into `extra_body`. | `llm.providers` |
| `local_batch_records.py` | Module | Reclaiming what a provider recorded in the project about a batch the registry no longer names. Only the agac provider records one; every other keeps its copy at the vendor. | `llm.batch`, `llm.providers` |
| `mixins.py` | Module | Shared mixins for access token handling, logging, context propagation. `OpenAICompatibleResponseMixin` (OpenAI, Groq, Ollama batch) reads a failed line's error as `HTTP <status>: <the body's error message>` and its status (`_extract_error_status`); a line that failed before any request has none. `OpenAICompatibleResponseMixin` reads an OpenAI-style batch line; `_no_answer` ends a message with no content with `error_wrapper.chat_no_answer`, the function the OpenAI and Groq online clients call: a `refusal` quotes the model (`refusal_text`), any other names the finish reason (`_vendor_label` names the vendor in it), and content the output limit stopped at an empty string is cut off before any answer. None of them is a failed line, so a retry resends only the cut-off one. `_answer_was_cut_off` is finish reason `length`. | `llm.providers` |
| `sdk_models.py` | Module | `build_sdk_models(*roots)` builds, on the calling thread, every pydantic model reachable from the given response types (through fields, unions, lists, dicts, `Annotated` and type aliases) that its SDK left to build on first use. The openai, anthropic and groq clients call it at import, so a process that imported the SDK before `agent_actions` (and so kept `DEFER_PYDANTIC_BUILD` lazy) parses no response by building a model on several record threads at once. Idempotent; a built model costs one attribute check. | `llm.providers` |
| `usage_tracker.py` | Module | Central usage tracking and quota summary used by providers. | `logging`, `llm.providers` |
| `agac/__init__.py` | Module | `agac` (Claude-branded) provider helpers (callbacks, config). | `llm.providers` |
| `anthropic/__init__.py` | Module | Anthropic-specific client wrappers and guardrails. | `llm.providers`, `anthropic` |
| `cohere/__init__.py` | Module | Cohere provider adapter for embeddings/inference. | `llm.providers`, `cohere` |
| `gemini/__init__.py` | Module | Gemini provider wiring (Google Gemini). | `llm.providers`, `google` |
| `groq/__init__.py` | Module | Groq provider binding for Groq Cloud inference. | `llm.providers`, `groq` |

| `ollama/__init__.py` | Module | Ollama provider with dual registration: `ollama_local` (no auth, `OLLAMA_HOST`, API-enforced structured output via `format` param) and `ollama_cloud` (Bearer auth via `OLLAMA_API_KEY`, `OLLAMA_CLOUD_HOST`, no structured output support yet). | `llm.providers`, `ollama` |
| `openai/__init__.py` | Module | OpenAI provider adapter with tool/window shaping. | `llm.providers`, `openai` |
| `tools/__init__.py` | Module | Tool discovery/registration for OpenAI function calling formats. | `llm.providers`, `tools` |
| `hitl/__init__.py` | Module | Human-in-the-loop provider for synchronous approval/rejection workflows. | `llm.providers`, `hitl` |
