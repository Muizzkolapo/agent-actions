# Config Manifest

**[> Architecture Deep Dive (ARCHITECTURE.md)](ARCHITECTURE.md)** — config loading pipeline, two-stage validation, defaults cascade, path resolution, DI system, and 20 caveats.

## Overview

What: Configuration and initialization surfaces for Agent Actions—schema models, environment
settings, DI container wiring, project initialization, and path management.

Why: Provides a single, consistent source of truth for how workflows are defined, validated,
and wired at runtime.

How: Models (schema + env) define inputs, path resolution anchors IO, and DI wiring connects
orchestration, prompts, and processing to concrete implementations.

| `schema.py` | Module | Workflow configuration schema (Pydantic models) with `extra="forbid"` on `WorkflowConfig`, `ActionConfig`, `DefaultsConfig`, `StorageConfig` (the workflow's own `storage:` block, strict-typed because its consumer reads the raw dict), `WorkflowConfig.batch_preparation_concurrency` (`BatchPreparationConcurrency`, an int 1-50, strict for the same reason: the most batch actions of a step that prepare at once) and `ChunkConfig` (the `chunk_config:` block, strict-typed because an undeclared key there is silently replaced by the hardcoded default at split time; it enters no config hash or stamp. `branch_origins` writes one sentence per branch naming the actions it defines (`'a', 'b' come from branch 'x' (branches/x.yml).`), for the cycle message and the preflight `Origin:`. `ExpectConfig` binds an expectation suite to an action via `ActionConfig.expect`, including `judge_budget: int \| None` (caps real `llm_judge` calls per action per run; Internal `_sends_elsewhere` and `_gathers` (`sends_elsewhere`, `gathers`) mark an action whose guard filter sends a record to another branch and one where such records come back (`record/elsewhere.py`). | `includes.py` | Module | Include of a shared branch file. `expand_includes` reads `branches/<name>.yml` for each `- include: <name>` entry, and `expand_workflow_includes` (pure: parsed data in, parsed data out) validates the branch file (`parse_branch`: keys, `branch:` equal to the file stem, each action an `ActionConfig`, action names that can take a `__` prefix, prompt store prompts only, no Jinja, no include), the entry keys (`include`, `as`, `inputs`, `defaults`, `override`, `remove`) and, in `_inclusion`, that no branch action has a reserved name (`RESERVED_AGENT_NAMES`, refused with the text a workflow without an include gives, naming the branch, the include and its `as:` instance), the input bindings and the names, then puts the branch actions in place of the entry with an `_include` origin. `as: <instance>` names the instance (`_prefix`: the action-name rule; instance names are unique, an include without `as:` taking its branch name): each branch action becomes `<instance>__<name>`, an input may be bound to any action (without `as:` only to one of its own name), and `_bound` renames every short name (branch actions, their version names, inputs and the version names of a versioned target) in the action's `dependencies`, `context_scope` lists (an optional observe entry written as a mapping by its `field`), guard clause (`renamed_clause`: only the root of a dotted field path, outside quoted strings and numbers; the text is otherwise kept), `version_consumption.source` and inline `llm_judge` `context` (`rename_judge_contexts`), and in the include's `defaults:`; a trailing `?` on a bare name is kept. The map rides as `_include.names`. A short name that is also a workflow action is refused (`_refuse_short_name_clashes`), except an input bound to the action of its own name. `Inclusion.label`, `final` and `local` name an entry and translate names. `instance_names` reads an action's map; the render step calls `alias_prompts` (the alias header of `prompt.aliases` before each prompt of an `as:` include) and `rename_schema_judge_contexts` (the `llm_judge` contexts of the action's own copy of its compiled schema, on its fields and in its `expectations:` block). `override:` maps a branch action to whole keys that replace the branch value (`null` removes the key; `name` and a key that is not an action field are refused, `schema` and `schema_name` count as one key, and the merged action must validate as `ActionConfig`); `remove:` leaves branch actions out; an override or removal that names no branch action is refused with the nearest name, and one action cannot be under both. `defaults:` is validated as `DefaultsConfig` (`data_source` is refused: it is a setting of the workflow) and is carried, not copied, as `_include.defaults` on each included action; the expander lays it over the workflow defaults with `layered_defaults`. `check_include_reads` runs on the finished render: a host action reads only declared `outputs`, a branch action reads only its branch, the actions its `inputs` bind and their versions; inside an `as:` include a read (or, before the workflow validates, a dependency) of a name that is no action, binding or framework namespace is refused naming the branch, the instance and its short names, and single-brace prompt text is left to the static checks, which report it as in a workflow without an include. A branch action that reads a bound workflow action by its workflow name, not through its input, is refused when `_bound` renames it (`_LookedUp` keeps the names a rename looked up and missed); a removal refusal names the include by `Inclusion.label` and the reader by its short name. A read includes the `llm_judge` context of the `expect` block the action gets from the expander (a named suite's rules read from `_Levels.root`, and preferred over an inline list as the run prefers them; a suite that does not load reads nothing; inside an `as:` include, where a suite's rules are not renamed, a short name that only a suite reads is refused by `_refuse_short_name_in_suite`, which gives the final name to write or says to move the rule to the action's schema or an inline list): `merge_expect` over the defaults (the workflow's keys over the project's), then `adapt_inherited_expect` with the kind and granularity from `inherited_routing_kind` and `resolved_granularity`, so a block with no rule of its own on a tool or FILE action reads nothing; for an included action the defaults are its instance defaults over those (`action_defaults`, by `layered_defaults`). The `context_scope` an action inherits counts too. `_Levels` computes it with the functions the load calls, in the load's order: `project_action_defaults` and `merge_workflow_defaults` (the workflow's defaults over the project's), `ActionExpander.defaults_for` (the include's defaults), `inherited_context_scope` (the action's raw directives over the defaults'), `project_agent_config` with `merge_over_agent_defaults` (the project scope for an action left with none), then `normalize_context_scope`; only then are the `observe`, `passthrough` and `drop` lists taken as reads. So an own directive that is null or not a list replaces the inherited one and reads nothing, and a workflow `context_scope:` that is null or empty leaves the project scope in force: a branch action that reads a host action through the workflow, project or include defaults is refused unless the action is a declared input, a host action that reads a branch internal through the workflow defaults is refused, and the refusal names the level in `(from 'context_scope' under ...)`. A `seed` reads nothing; an unknown directive, a defaults level that the load refuses, and a project `context_scope` that is not a mapping are left to the load, so the user gets the message a workflow with no include gets. A read of a removed action is refused first, when the defaults validate, on each action that validates as `ActionConfig`: a branch reader names every reader in the branch, with the defaults level of each reader that only inherits the read, through `context_scope` or an inherited `expect` (`_scope_origin`; the advice then adds an edit of those defaults, and says that in an override `null` takes away an inherited directive while a list is added to it), and a host reader is told the output is left out under `remove:`; a binding to a removed output is refused at expansion. The other checks run only on a workflow that validates as `WorkflowConfig`; so no check reads a malformed shape, and a malformed workflow is left to the validation after the render, which refuses it with the message it gives a workflow with no include. A hand-written `_include` is refused in a workflow and in a branch file; `schema_name:` in a branch action is validated as `schema:`, as the render step reads it. Every refusal is a `ConfigurationError` with the workflow file under `file_path` (shown on the CLI `File:` line) and the action under `action_name`. Every refusal names the workflow file in its text; a refusal about a branch file or a branch action also names the branch file and the action (a branch-file refusal begins `Branch '<name>' (branches/<name>.yml), included in <workflow file>`, then `, action '<action>'` when it is about one action). A dependency cycle is the exception: `WorkflowConfig` refuses it and names only the branch file of each branch action in it. `has_include` tells whether parsed data has an include entry. A router (a built-in route action, `is_router`) may be read from any instance: the first action of each of its branches reads its case. Two iterations of one loop read each other (`Inclusion.loop`, from the include entry's internal `_loop` key, rides as `_include.loop`). `inherited_granularities` gives the granularity each action runs at once it inherits the defaults, with `_Levels`. `workflow_label()` names the workflow file as a refusal names it. | `configuration`, `validation` |
| `routes.py` | Module | `- route:` and `- join:` entries. `expand_routes` (after the includes) turns `- route: <name>` (`on: <action>.<field>`, `cases:` value → include instance or list of entry actions, required `default:` branch or `filter`; YAML's bare `on` key arrives as `True` and is read as `on`) into a built-in `agac.route` tool action that observes the field, depends on its action and writes `case` (inline schema with the case enum; under `default: filter` an ordinary guard `<field> IN [...]`, `passthrough_on_error: false`), and gives each entry action the guard `<router>.case == "<case>"` (`default` for the default branch), `_sends_elsewhere`, the router as a dependency and `<router>.case` in its observe list. The entries of an instance are its actions that read no other action of it. `- join: <name>` (`of:` actions, or an instance with one output) becomes a built-in `agac.pick` action that depends on and observes `<action>.*` of each, with `_gathers`. Refuses: no default, a case or default naming no branch or an unknown name, a non-string, empty, quoted or `default` case value, an entry in two cases, an entry with its own guard or that is the field's action, an action reading two cases' branches (dependency or context_scope) short of a gatherer, unknown keys, and a router or join name that is taken, breaks the name rule or ends in `_<digits>` (`entry_name`, which `loops.py` uses too). `finish_routes` (after schema compile) refuses a case value outside the field's `enum` and, under `default: filter`, an enum value with no case; and gives a join without a schema the union of its sources' compiled fields, none required, `additionalProperties: true`. A router or join the expansion makes is an action a later entry can name (`on:`, `cases:`, `default:`, `of:`); a join refuses a versioned source; `finish_routes` refuses a router on a field whose schema type is not `string` or whose `enum` holds a non-string (`null` is accepted in a type list and an enum, and the message names the type when the type is the cause); `_warn_partial_joins` warns of a join that covers some but not all branches of one router, except a join that closes a router inside one branch of it. Under `default: filter` the router guard also lets through a value that is set and is no string, so `route_case` fails it. | `config`, `llm.providers`, `record` |
| `loops.py` | Module | `- loop:` entries. `unroll_loops` (called by `expand_workflow_includes` before it reads the include entries) checks a `- loop: <name>` entry (`include` a branch file, `max_iterations` 1-10, `inputs`, `feedback` input → branch action listed under `outputs`, `until` a guard clause on branch fields up to `result` (parsed with `WhereClauseParser`, `clause_paths`), `result` a branch output with no versions; no own guard on an entry action, no guard or version source reading a feedback input) and replaces it with `max_iterations` include entries `as: <name>_iter<k>` (`instance_name`; `_iter` keeps an instance name from ending in `_<digits>`), each carrying the internal key `_loop` (refused when written), plus a built-in `agac.pick` action named after the loop that depends on and observes `<name>_iter<k>__<result>.*` of every iteration, last first, with `_gathers` and the loop settings under `_builtin.loop`.
