# LSP Manifest

## Overview

Language Server Protocol helpers that index agent workflows/prompts/tools, resolve
references, and expose hover/definition/navigation for editors.

## Modules

| Name | Type | Description | Signals |
|------|------|-------------|---------|
| `models.py` | Module | Data models (`ProjectIndex`, `ActionMetadata`, `PromptDefinition`, `ReferenceType`, `Location`, `ParseError`) describing references, workflows, prompts, schemas, and tools. | `lsprotocol`, `pygls` |
| `indexer.py` | Module | Scans workflows/prompts/tools/schemas, builds `ProjectIndex`, and reads each workflow from its render (`jinja_source`), so a workflow that imports macros keeps its actions; a workflow that does not render goes into `ProjectIndex.parse_errors` with no actions. The line pass skips the lines the render dropped, takes a `- name:` line as an action only where the render defines one, and records no reference on a line that holds a Jinja tag. Builds and records metadata used by navigation and hover. Provides `find_all_project_roots()` for multi-project workspace discovery. Action values (`guard`, `context_scope`, `output_field`, `versions`) come from the PARSED document; the line pass supplies only positions and reference ranges. `output_field` defaults resolve workflow `defaults:` then `agent_actions.yml`'s `default_agent_config`. Guard-language keywords come from the operator registry. Uses `get_tool_dirs` from `path_config`. A `schema: dispatch_task('fn')` value is told from a schema file name by `schema_dispatch_function`, the test `agac inspect` and `agac run` use, so it records no schema reference. | `ruamel.yaml`, `yaml`, `logging`, `config.schema`, `input.preprocessing.parsing.operators`, `output.response.dispatch_injection` |
| `jinja_source.py` | Module | `render_workflow_source` renders a workflow file with the Jinja load step of `agac` only (`new_load_render`; no prompt fill, no versions, no file written) and maps each action to the file and line that define it, a template macro line included. The rendered text is read with `yaml.SafeLoader`, the loader `agac` uses. `MarkingLoadRender` tags each `name:` line, and each other workflow line outside a tag, with a YAML comment; a name tag is read on the rendered line of each parsed action, and a workflow line whose tag is missing from the output is one the render dropped (`live_lines`). The body of a `set` or `filter` block gets no tag, because a tag would change the text it holds or outputs; a `filter` body is live where its closing line is live. A `macro` body keeps its `name:` tags but gets no line tag, because it is output where it is called. A `{% raw %}` line is tagged, because raw text is output as written. The marked render, with its tags removed, must equal the plain render line for line (lines split where PyYAML splits them); when a tag changed the render, no action gets a source line. A workflow file that is a `$file.key` prompt reference loads as `agac` loads it (`_load_yaml_content`) and gets no source lines. Any render failure raises `WorkflowRenderError` with a 0-indexed workflow line. | `jinja2`, `yaml`, `errors`, `prompt.render_workflow`, `prompt.deferred_values` |
| `diagnostics.py` | Module | Collects LSP diagnostics: unresolved references, duplicate actions, guard clause validation. A guard reads the record as stored, so a clause is reported only where the file can prove it resolves nowhere: a bare name with no promotion available (suggesting the dotted spelling; at a first action, which names no upstream, `source.<name>`, since its record holds the staged row there), or a dotted reference whose namespace no action in the workflow writes. Which fields a namespace holds is never judged. A versioned action produces `base_1`, `base_2`, ... and not its own name. A workflow in `parse_errors` gets one Error, `Workflow does not render: <message>`. A diagnostic about an action that a template macro defines sits at line 0 of the workflow file and names the template line. | `lsprotocol`, `models`, `resolver`, `utils.constants`, `record.envelope` |
| `completions.py` | Module | LSP completion providers for context_scope blocks, guard conditions and `versions:` blocks. `build_guard_completions` delegates to `collect_available_guard_variables` for variable list; `build_versions_completions` reads `VersionConfig.model_fields`, so the editor cannot offer a key the loader refuses. | `lsprotocol`, `diagnostics`, `config.schema` |
| `resolver.py` | Module | Detects references at cursor positions (`get_reference_at_position`) and resolves them to file `Location`s (`resolve_reference`). | `lsprotocol`, `pathlib`, `utils` |
| `server.py` | Module | `AgentActionsLanguageServer` setup plus LSP handlers for initialize/definition/hover using the indexer/resolver/navigator. The custom request `agentActions/renderedWorkflow` returns a workflow's rendered text and action source lines to the VS Code extension, which cannot run Jinja. Watches `templates/**/*.jinja2` and `*.j2`, so a macro edit reindexes. | `pygls`, `lsprotocol`, `utils` |
| `utils.py` | Module | Shared LSP utilities: `uri_to_path()` for URI conversion, `is_in_dependencies_context()` and `is_in_context_scope_list()` for YAML block detection. | `pathlib` |
| `__main__.py` | Entry | Enables `python -m agent_actions.tooling.lsp` invocation. Delegates to `server.main()`. | — |
