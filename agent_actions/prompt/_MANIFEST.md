# Prompt Manifest

**[> Architecture Deep Dive (ARCHITECTURE.md)](ARCHITECTURE.md)**

## Overview

Prompt utilities cover generation, templating, formatting, context scope helpers,
and service wiring used by CLI commands and runtime agents.

## Sub-Modules

| Sub-Module | Description |
|------------|-------------|
| [context](context/_MANIFEST.md) | Builds rich context scopes and static prompt loaders. |

## Modules

| Name | Type | Description | Signals |
|------|------|-------------|---------|
| `deferred_values.py` | Module | `LoadRender` is one load of a workflow file. A `{% cache_point %}` tag of a prompt stays a tag through the load, whether the prompt is kept for the record or rendered now. It wraps every `prompt:` value of the file and of `templates/`, and every other value that names a version variable, in a tag that sees exactly what Jinja has bound where the load reaches it, in block or flow style, on its key's line or the lines below it. A value whose names are all bound renders at load as before. A prompt reading a name a record supplies (`source`, an action of the workflow, a version variable) is left whole for the per-record render: its top-level `{{ }}` tags that read load-time names and nothing else render into it, and the load-time data its other tags read is set at its top (`{% set name = ... +%}`); a macro, function or include it would need per record fails the load. A `LoadedPrompt` (the text `load_prompt` returns) that a prompt's `{{ }}` tag outputs as it is, in either case, goes into the YAML as a token replaced by the text once the YAML is parsed (`fill_loaded`, or within the per-record text), so its lines are never read as YAML. A value reading a version variable renders per version (`render_version`) or, outside a versioned action, without one (`fill_values`). The environment is `StrictUndefined` except while a `templates/` file's top level is imported, and records every name it looks up and misses; `check` fails the load on one a record or a version supplies. A name a prompt reads that the render finds undefined is taken for an action the file names by a tag (`name: {{ n }}`) and the file rendered again; `check` fails the load with the first error when no parsed action has that name. An `{% include ... without context %}` is compiled so its text reaches a macro, set block, call body or filter block that collects output, where Jinja's own code makes a generator of it. `fill_store_prompt` gives a prompt-store prompt that reads a name `templates/` sets the same treatment, rendered as a lone `prompt:` block scalar of the load; any other store prompt is returned untouched. `written` gives the parsed data with each left value as the file writes it, for the editor; `written_line` puts each left value, anchor or tag included, back into a rendered line as the file writes its first line, and `written_text` puts each left value into rendered text as one JSON line of that value, with each character YAML does not take as written escaped. A left value that does not parse as YAML on its own (it starts with `{{`) is read by YAML with its `{# #}` comments removed and each other Jinja tag held out, then the tags put back into its keys and values, so its YAML comment is dropped as agac drops it once rendered. | `prompt_generation` |
| `aliases.py` | Module | The alias header of an `as:` include. `with_alias_header` puts one `{% set short = final %}` tag before a prompt for each renamed short name it reads (none: the prompt is returned unchanged), on its first line so line numbers hold, with an empty `{{ "" }}` tag when the prompt starts with a newline that `trim_blocks` would eat. `prompt_aliases` gives the names a top-level `{% set a = b %}` binds to a bare name, only where the action's `as:` map (`header_names`, read from `_include.names`) gives `a` the final name `b`, so a `{% set %}` a prompt writes itself reads as before; a name set twice at the top level is left out; every static reader of prompt references follows them with the action's map (`ReferenceExtractor`, `extract_action_names_from_template`, the prompt-contract check). | `prompt_generation` |
| `formatter.py` | Module | Template helpers for prompt formatting and escaping. | `prompt_generation` |
| `handler.py` | Module | `PromptLoader` and prompt builder utilities. `PromptLoader.discover_prompt_files` lists the `.md` files in the project's `prompt_store/` and each `agent_workflow/*/prompt_store/`, recursively; `PromptLoader.load_prompt` reads a file only from that list and raises `ValueError` naming every match when a file name is there more than once, or the searched folders when it is not there. Inside a `PromptLoader.record_loads()` block it also adds each file it reads, once, to the list the block yields; outside one it records nothing. `PromptLoader.load_prompt` accepts `project_root: Path \| None`; `PromptLoader.load_prompt_expanded` also replaces each `{{ load_prompt("...") }}` tag in the prompt by that prompt, recursively, refusing a cycle or a call it cannot expand (the `$` reference, the load-time `load_prompt` global and `PromptFormatter` use it). | `logging`, `cli` |
| `prompt_utils.py` | Module | Misc utilities (token counting, template expansion). | `prompt_generation`, `logging` |
| `render_workflow.py` | Module | Renders workflows into final YAML via templates. `render_pipeline_with_templates` accepts `project_root: Path \| None`. Right after the parse it refuses a workflow file in the `agents:` format (`config.schema.refuse_agents_format`), before the includes expand; `workflow=False` (the project file `agent_actions.yml`) skips that check. The load renders through `deferred_values.LoadRender`: an action's prompt that reads what only a record supplies is left whole for the per-record render, a versioned action's other values that read a version variable render per version at expansion, and a name nothing defines fails the load. Its `load_prompt` global returns a `deferred_values.LoadedPrompt`, which a prompt's tag puts in as written, whatever its lines and the prompt's YAML style. Its `env(name, default)` global returns the process environment's variable (the CLI loads the project's `.env` into it first), or the default when unset; unset with no default fails the load with a `TemplateRenderingError` naming the variable and the workflow file. An empty value counts as set. The `templates/` folder loads in file-name order, each file's top level run once and after any file whose name it reads; the files' modules share the globals, so a file reads any other's macros and variables whatever the files are called, and of two files defining a name the one that ran later is the global. A `prompt: $file.Prompt` resolved after the parse goes through `LoadRender.fill_store_prompt` with the names `templates/` set, so it reads them as a prompt written in the file does: the per-record render has no `templates/`. After the prompts resolve, `alias_prompts` puts the alias header before each prompt of an `as:` include; after the schemas compile, `rename_schema_judge_contexts` renames the short names in the `llm_judge` contexts of each such action's own copy of its compiled schema; both run before `check_include_reads`. Right after the includes are expanded, `config.loops.expand_loops` wires the iterations of each loop and `config.routes.expand_routes` replaces each `- route:` and `- join:` entry; once the schemas are compiled, `finish_routes` checks each router's cases against the `enum` of its field and gives each join its schema, then `finish_loops` checks each loop's `until` fields, its granularity and the readers outside it, and gives its pick the result's schema. Their refusals carry the workflow file (`_with_file`). | `cli`, `prompt_generation` |
| `renderer.py` | Module | `JinjaTemplateRenderer` for Jinja rendering, `ConfigRenderingService` for config loading; `render_and_load_config` returns the rendered workflow text once it validates; its schema folder check runs when the workflow defaults leave JSON mode on, or when an action sets it or gets it from the `defaults:` of its include. | `cli`, `validation` |
| `message_builder.py` | Module | `MessageBuilder` — unified message assembly for all LLM providers. `LLMMessageEnvelope`, `ProviderMessageConfig`, `PROVIDER_MESSAGE_CONFIGS` registry. `build` is the one builder: every online client and every batch client calls it with the same arguments, so a batch line carries the messages the online request carries (there is no separate batch builder), and both get the `PromptTooLargeError` pre-check: the estimate (characters / 4) is measured against `context_window` when the caller passes the action's setting, else `_MODEL_CONTEXT_LIMITS` (the current Claude models included, at the windows Anthropic documents), else 128,000 tokens; every vendor client passes `context_window`, online, in batch and for judge calls. A context string is embedded as written, with no brace escaping; a context dict is encoded as the online call encodes it (`ensure_json_safe`, then `deep_json` with `ensure_ascii=False`), at any depth, for every provider. `build` places cache boundaries by one rule (`_place_cache_boundaries`), as lengths of leading content on the message that holds the prompt (`LLMMessage.cache_boundaries`): one at each of the `cache_points` it is handed (lengths of leading prompt, from the template's `{% cache_point %}` tags) and, asked to (`enable_prompt_caching`), one at the end of the prompt part (`LLMMessage.static_len`); never on the record content. A boundary changes no text: `LLMMessage.segments()` gives the content in order with the boundaries between, `to_dicts()` gives the content whole, and each vendor client decides what a boundary is (Anthropic's `message_params` ends a marked text block at each). Only the Anthropic clients hand `build` cache points or ask for the boundary at the end. Cache points that do not ascend within the shared prompt raise `ValueError`. `shared_prompt_len` ends the prompt part early, where a repair call's feedback begins, so the feedback goes unmarked after the prompt and the marked block is the one the first call sent; a length outside the prompt raises `ValueError`. No boundary is placed where a text block it would split off is blank, a block the API refuses. The Anthropic clients ask only when `cache_scope.prompt_is_shared` holds. | `llm`, `prompt_generation` |
| `cache_scope.py` | Module | Whether a call's prompt and tools are the same for every record; each check fails closed. `record_reads_in_prompt` lists what the prompt template reads that can differ per record: every name Jinja reports as read without being bound (`meta.find_undeclared_variables`, which follows `for`, `set` and macro scope), except `version`, `workflow`, `loop` and version params; while any `seed` key has `select_by`, every `seed` read not through a constant key naming a key without one; every `dispatch_task(...)` call; the `random` filter and the `lipsum` global; and, when nothing else counts, a `seed` read while a seed file holds a `dispatch_task(` call or cannot be read, or a version name read while a version value holds one. `schema_dispatches` lists the `dispatch_task(...)` calls anywhere in the action's schema, inline or loaded by `schema_name`. `prompt_is_shared` is false for either, or when the call's config carries `_request_varies_per_record` (a judge call, a schema the record chose, or a repair call whose prompt does not begin with the rendered prompt). `cache_point_use` reads the `{% cache_point %}` tags of an action's template: how many, whether one sits in a loop, a macro, a call block or a block that captures its text, and what the text before the last one reads that changes on every render (`dispatch_task`, `random`, `lipsum`) or that is not `source` or data every record shares (an upstream action's field, a per-record seed). `CACHE_POINTS_KEY` (`_cache_points`) carries a rendered prompt's cache points on one call's config and on a batch row; `cache_points_of` gives them to a client, none on a call marked `_request_varies_per_record`. `repair_call_scope` gives a repair call `SHARED_PROMPT_LEN_KEY` (`_shared_prompt_len`), the length of the rendered prompt its prompt begins with, or that key when it does not begin with it. | `llm`, `processing`, `validation`, `expectations` |
| `service.py` | Module | `PromptPreparationService`: applies context scope and renders the per-record prompt. The rendered prompt holds no trace of a `{% cache_point %}` tag; `PromptPreparationResult.cache_points` is the length of the text before each tag the render reached. A render that runs past the recursion limit (`{{ value }}` prints a dict or list with `str()`) fails that record with `RecordContextError`, naming the deepest field, its depth and the limit, and pointing to `\| tojson`; a recursion no field half the limit deep explains (a recursive macro) fails as any other render error. A template reading a field of a null dependency namespace fails with `TemplateVariableError` whose `null_namespace_hints` say what the record shows about why (`null_namespace.diagnose`); a guard is named only when the record shows that action's guard skipping it. A field a present namespace (or a mapping inside it) lacks is reported as `ns.field` with "'ns' has no field 'field' (it has: ...)", not as a namespace nothing supplies; a mapping held at several places is named by the one the template reads, or not placed at all, and the search is bounded. `load_seed_data` is the one loader of an action's declared seed, for the prompt and for `processing/guard_context.py`; `shared=True` reads through `static_loader.shared_static_data_loader`, whose values are shared and read-only. The guard reads shared; both prompt paths read shared too unless `reads_seed_only(context_scope)` is false (a `drop` or `passthrough` names a `seed.` field), so every record of a batch reads one parsed copy rather than holding a parse of its own. `prepare_prompt_with_field_context` leaves out a `seed` the guard context carries and loads its own, under the same rule. | `logging`, `prompt_generation` |
| `context_block.py` | Module | Which observed fields a request sends in its context block, beside the rendered prompt. `context_block(context, agent_config, prompt)` reads the action's `context_block` (`auto`, the default; `all`; `none`): `all` returns the context, `none` an empty one, and `auto` the context without each field `printed_fields` finds in the template whose rendered text (`str(value)`) the request's prompt holds, so a repair prompt that does not repeat the first prompt still gets the field. `printed_fields` lists the paths an output tag at the top level of the template prints as they are (`{{ ns.field }}`, `{{ ns['field'] }}`, deeper paths too), following a top-level `{% set a = b %}` alias; a tag in a block, loop, condition or macro, or with a filter, does not count. A namespace left empty is dropped. Under `auto`, a vendor whose message shape sends the record in its own message (`MessageRole.SYSTEM_PLUS_USER`: Ollama) keeps every field. A context that is not a mapping, and a tool or hitl action, are returned unchanged; a template that does not load leaves the context whole. Called where a request's context is encoded (online `create_dynamic_agent`, batch `BaseBatchClient.prepare_tasks`), by the trace writer and by the batch prompt debug print, so the token guard, the trace and the request agree. | `llm`, `processing` |
| `cache_point.py` | Module | The `{% cache_point %}` tag of a prompt template: it renders to no text and says the text before it is shared by many records. `PROMPT_EXTENSIONS` is given to every Jinja environment that reads a prompt (the per-record render and each static reader); without it the tag is a syntax error. `CachePointExtension` renders the tag to a mark drawn for the process, which no record text can hold, and keeps the line break after a tag that follows text on its line (`trim_blocks` would eat it), outside `{% raw %}` blocks, whose text stays as written; `take_cache_points` removes the marks from a rendered prompt and returns the length of the text before each, and runs only when `has_cache_point` finds the tag in the template. `CACHE_POINT_TAG_PATTERN` is the tag as a template writes it; the config hash of an action removes it with `without_cache_points`, which also removes the line of a tag alone on its line, so a tag is not an edit. `KeptCachePointExtension`, the workflow load's, renders the tag to itself, so a prompt the load renders still holds it for the record. `MAX_CACHE_POINTS` (3) is the most a template may hold; `is_cache_point` tells the node a tag parsed to. | `prompt_generation`, `validation`, `llm` |
| `jinja_env.py` | Module | `DictKeyFirstEnvironment`: dot and subscript access on a mapping read only its keys -- a key wins over a same-named attribute, and a key it lacks is undefined even where a dict method has the name (calling it, as in `ns.items()`, still calls the method) -- and `tojson` encodes with `deep_json`, so it renders a value at any depth with the text Jinja's own gives. Given `place_of`, a key a mapping lacks raises `MissingFieldError` naming the mapping's place and the field, once the undefined is used. | `prompt_generation` |

## Dependencies

| Package | Direction | Why |
|---------|-----------|-----|
| `workflow` | inbound | Calls PromptPreparationService during action execution |
| `processing` | inbound | TaskPreparer delegates prompt rendering to PromptPreparationService |
| `llm` | inbound | Provider clients use MessageBuilder for prompt assembly |
| `validation` | inbound | Prompt validator checks prompt file references |
| `config` | outbound | Reads prompt paths and project root from config utilities; `render_pipeline_with_templates` calls `config.schema.refuse_agents_format` on the parsed workflow |
| `output` | outbound | Uses SchemaLoader to inline named schemas during rendering |
| `input` | outbound | Uses StringProcessor for dispatch_task() call resolution |
| `expectations` | inbound | The judge marks its calls with `cache_scope.REQUEST_VARIES_PER_RECORD_KEY` |
