## 0.2.8 - 2026-08-02
### Bug Fix
* Fix docs dashboard accuracy — expand versioned actions (43→52), search agent_io* directories for manifest/runs/logs
* Clear node-level disposition when an action begins executing. Eliminates the 'Stale guard-skip disposition' warning that fired on reruns after a prior dependency-skip, and removes the read-side heal block in _resolve_completion_status.
* Passthrough namespaces now merge at content level as siblings of the action namespace, so downstream observe and passthrough resolve correctly. Added warnings when bare observe keys collide across namespaces and when a seed field is both auto-injected into a prompt and listed in observe (double injection).
* Flat-mapping schema fields are no longer force-required by default; required-by-default is opt-in via required_by_default, and optional or unmarked fields are respected. Top-level required arrays declared on a schema are now honored.
* Guard conditions that compare incompatible types now warn at runtime and preflight instead of silently misbehaving, and union-typed fields survive schema validation.
* FILE-tool input now namespace-qualifies observed fields that collide across sources (for example version fan-in), so a tool receives ns.field instead of a silently overwritten bare key.
* LLM outputs are now deeply validated against the schema: numeric minimum and maximum, additionalProperties false, and per-element validation of nested arrays are enforced and drive reprompt, instead of only top-level shape checks.
* Fan-in grouping now keys the whole record pool on one universal correlation field instead of the first field present per record, fixing silent half-merges when branches have asymmetric correlation keys.
* Preflight seed checks now use the same directory resolution as the runtime (workflow root, then project root). A declared seed reference with no seed directory anywhere is a blocking startup error instead of a silent skip.
* A timed-out human-in-the-loop review now reports its true reviewed count from the partial per-record snapshot instead of always reporting 0 of N; reviews were persisted and resumable all along.
* FILE-tool observe collisions are now flagged at preflight, not only at runtime, so the failure surfaces before execution.
* FILE-tool output is now schema-validated per record by unwrapping the FileUDFResult envelope, removing spurious empty-object warnings on healthy tools and catching real per-record violations.
* Online prompt-preparation failures are now classified as FAILED, so a total failure is no longer reported as success.

## v0.2.0 - 2026-05-23
### Breaking Change
* Removed cross-workflow chaining: upstream: config key, --upstream/--downstream CLI flags,
WorkflowOrchestrator, and VirtualAction injection. Workflows are self-contained.
Users with upstream: in config will see an unknown-key warning.

### Enhancement or New Feature
* v0.2.0 Quality Hardening — 25 fixes from comprehensive codebase audit:
- Storage errors now propagate instead of silently returning COMPLETED
- Schema migration uses ALTER TABLE instead of DROP TABLE (preserves data on upgrade)
- Disposition table clears conflicting rows before writing terminal state
- --fresh flag clears all state (source_data, batch recovery, batch registry)
- Preflight key verifier fails on infrastructure errors (SSL, proxy, DNS)
- Batch SQLite commits batched (10-50x perf improvement for 1000+ records)
- Config change detection invalidates stale completed actions on prompt/model/schema change
- Retry Ctrl+C writes manifest checkpoint for crash recovery
- LLM hardening (token overflow guard, prompt injection fix, parse error parity across providers)
- Source GUID uses uuid4 to prevent collision on duplicate/expanded records
- Thread safety for ActionStateManager and atomic_json_write
- O(n²) lineage lookup replaced with dict index
- Dead code removed (12 functions, 11 aliases, ghost mistral directory)
- 33 new tests covering 7 previously untested critical paths
- 15 false-positive tests fixed
- Observability gaps closed (record identity in logs, LLM call duration, batch events)
- DB maintenance (WAL checkpoint, disposition cleanup, prompt trace retention)

### Bug Fix
* Batch/online content parity: first-stage batch actions now synthesize the source namespace,
matching online mode. Fixes source.page_content resolving as null in batch workflows.

* Batch disposition dedup prevents UNIQUE constraint violations on resume.
Deferred dispositions now cleared using per-action name instead of workflow name.
Prep failure logs show source_guid instead of array index.
