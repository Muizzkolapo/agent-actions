## 3.0.0 - 2026-11-08
### Breaking Change
* A config edit no longer re-runs anything. An edit to an action's model, prompt, schema, guard, context_scope or dependencies used to reset the action and every action reading it, so the next run answered every record again. Now the answers they hold stand, records not yet answered use the edit, and each run warns which action was edited and what changed. Use the new `agac run --rerun <action>` to answer an action and its readers again under the edit, or `--fresh` for the whole workflow. Each prompt trace row now records the config it was answered under (`answered_under`).
* A change to a first stage's staged input no longer answers every record again. Adding, removing or changing a staged file used to reset that action and every action reading it, as `--fresh` would for them. Now the records the change left alone keep their answers; a record added, or one whose content changed (a new record), is answered; and a record no staged file holds any more leaves nothing behind — its rows, its dispositions (a failure included, so `agac retry` no longer offers it) and its checkpoints go at that action and at every action reading it, once a run has read every staged file (not under a file limit, after a file failed to read, or under `agac retry`). An edit met beside the change is named as for a config edit. Use `agac run --rerun <action>` to answer every record again.
* A FILE tool's named observe field keeps its bare key beside a wildcard. A field named in observe was renamed to its qualified key whenever another namespace was observed by wildcard, and preflight called that a collision. Now the named field is delivered bare, a wildcard field of the same name arrives qualified (ns.field), and preflight reports a key only when the declared schemas show a real collision. A tool that read the qualified key of a named field beside a wildcard must read the bare key.
* `agac inspect` and `agac run` now refuse an action whose named schema file does not exist, before any action runs. An LLM action was refused only when another action read one of its fields, after the actions upstream had run; a tool action ran with no schema checked. A workflow with a tool naming a missing schema ran before and is refused now.
* An action or `defaults:` block that writes `constraints`, `enable_caching`, `max_execution_time` or `where_clause` is now refused at load. The error names each key and its replacement: write a `constraints` instruction into the action's prompt; `enable_caching` is `enable_prompt_caching`; `max_execution_time` has no replacement; a `where_clause` filter is a `guard:` with a `condition` and `on_false: filter`. The four keys validated and configured nothing: no runtime module read them, so a `where_clause:` filtered no record. The action-scope guard path that no config could reach is removed with them; a guard is evaluated per record, as documented.
* A record a FILE tool or FILE HITL action cannot be handed, because it lacks a field the action observes or its source cannot be resolved, is now a failure of that action: it is counted, its disposition is failed with a reason naming every missing field, and agac retry can reach it. Before, the record was skipped outside the count, the action read as complete, and when every record was skipped the action was labelled guard-filtered with no guard set. RECORD mode also names every missing observed field instead of the first. A record the action's guard skips is still a guard skip. Because a refused record is now failed rather than skipped, agac retry reaches it, and a FILE action whose every record was refused ends failed instead of skipped.
* A FILE tool's roll-up row (an output with source_index: None) carried the first input's upstream fields and state history, so a reader below saw one input's source and values as the roll-up's. The row now carries, from each upstream namespace, only the fields equal on every input of the file, and none of the first input's history. A value every input shares still reaches the actions below. An action below a roll-up that observes a field whose value differs between the inputs (`flatten.summary` on a roll-up over several pages) no longer finds it on the roll-up row and fails that record; observe a field the inputs share, or read it from the rows that have it.
* An action with `schema: dispatch_task('fn')` now declares `schema_options:`, the list of schema names the function can choose. The function returns one of those names; a returned schema definition is refused. `agac inspect` loads every option before any action runs, checks a downstream read against all options, and refuses a `dispatch_task` inside a fixed schema's fields.
* skip_condition, and its old spelling skip_if, is refused at load with a hint to skip records with a guard (condition plus on_false: skip). No actions: workflow could set it, and on the older agents: surface its model and its only reader disagreed on its shape, so it rarely did anything. SkipConditionStrategy and SkipConditionConfig are removed.
### Enhancement or New Feature
* Declare OpenAI-compatible endpoints in an `endpoints:` block of agent_actions.yml and select one with `model_vendor: <name>`. An endpoint has a base url (or one `${ENV_VAR}`), a credential from an environment variable, a command or none, extra headers and a timeout; it runs with structured output only, and a reply that does not match the schema fails the record. Secrets read for an endpoint are masked in logs by value.
* Set `request_timeout` (seconds) on an action, in a workflow's `defaults:` or in the project's `default_agent_config:` to bound each online LLM request. A request still unanswered after that long fails the attempt as a network error, which `retry:` retries like any other, and the record fails naming the timeout once the attempts run out; a hung request no longer holds a run indefinitely. It is passed to each provider SDK as its own per-request timeout and outranks a declared endpoint's `timeout_seconds`. Unset, nothing changes: each SDK keeps its own timeout. Zero, a negative number or a non-number is refused at load. Editing it is not a config edit.
* An online LLM action can send several records at once with `record_concurrency` (1-32, on the action, in `defaults:` or project-wide; default 1). At most that many records are in flight per action (an `llm_judge` with `votes` sends that many calls for each); each record is checkpointed as its answer arrives, and the output keeps input order. It is refused on tool, hitl and batch actions that write it, and ignored when they inherit it.
* A guard clause can compare two fields, such as `score_review.score >= seed.thresholds.min_score` or `extract.score < extract.limit`. Preflight checks a field on the right as it checks one on the left, so a misspelled action name, schema field or seed key is refused on either side. A record that lacks a field does not match, and `on_false` decides what happens to it; it no longer makes the guard refuse every later record. An undotted name on the right, such as `status == approved`, is still refused as an unquoted string.
### Under the Hood
* The retry reference quotes the warning a retry gives for an edited action and says how --rerun follows it; processing notes no longer describe a stopped action's clear as depending on its config.
* agac run --rerun logs "<action> is running again: resetting what reads it" once per reset, not three times: only the code that resets the readers logs it. The prompt traces reference says a resumed action keeps the traces of its failed attempts, and how to read the latest per record.
* Importing agent_actions.output.response.loader no longer sets the framework's logging up, which turned agent_actions propagation off and cleared its handlers wherever that import first ran. The test fixture also keeps caplog propagation on through any setup a command run in-process makes.
* Trim the integration-test module docstrings and the `agac run` help docstring to 10 lines or fewer
* A test pins that every consumer of a version merge holds every record across repeated parallel runs: five versions over three staged files, every merge holding all five votes.
* `LockDefaults.SIMPLE_LOCK_TIMEOUT_SECONDS` is removed. No code read it; the one file-lock timeout in use is `ATOMIC_LOCK_TIMEOUT_SECONDS`, read by the run tracker. The internal defaults page lists only that one.
* An action's kind is set once when the config loads, from kind (also from defaults:) or model_vendor, and every site reads kind alone. The sites used to decide again, each by its own rule, so agac inspect and agac run could treat one action differently: a model_vendor of Tool is now a tool everywhere, and the static analyzer ranks hitl over tool as the expander does.
* The guard-skip and failed-check counts on the run line come from what one execution's collections returned (CollectionStats.guard_skipped and checks_failed, gathered by a counter the executor opens around the run or batch check), not from tallies kept on the storage backend and taken twice. A path that skipped the completion take can no longer leave a stale count, and StorageBackend loses five methods, including guard_skips_collected, which only tests called.
* tests/unit/input passes when run alone in file order. A guard evaluator test patched build_field_context_with_history while prompt.service was first imported, so that module kept the mock and later prompt builds read its fake source.
* The docs site pins react and react-dom to the same exact version (19.3.1), and Dependabot updates the two in one pull request. A bump of react alone had left react-dom at 19.3.0, and the docs build refuses mismatched React versions, so Deploy Docs failed on every commit to main.
### Bug Fix
* An action named `function` now loads instead of being refused with "missing type-specific key(s): code_path". Pre-flight checks that depend on an action's type now read its `kind`, not its name.
* An edit to a generation setting (temperature, max_tokens, top_p, stop, frequency_penalty, presence_penalty) is now named as an edit, like a model or prompt edit, until --rerun answers the action under it; a stamp written before this is left alone.
* An edit to the code of a tool or UDF guard is now named as an edit of every action its file serves, until --rerun answers the action under it. The whole file the UDF was loaded from counts; modules it imports do not. A stamp written before this is left alone.
* An array schema whose items has no type is refused with a message naming the schema, instead of being read as a list of objects that rejected every string the model returned. Items with properties and no type are still read as objects.
* additionalProperties: true at the root of an array schema now lets a tool's records carry fields the schema does not list; it was ignored, and every such record failed validation. A flag under items still wins.
* agac run preflight now warns when a tool or guard UDF reads a bus key no action is named, such as its upstream's impl name, which reads an empty dict silently. agac validate-udfs already warned; the two share one scan.
* A tool file that fails to import no longer stops every workflow from starting: agac run skips it with a warning naming the file. A workflow naming a tool or guard UDF that is not loaded is refused at preflight, before any action runs, by an error naming the action and each skipped file. validate-udfs and list-udfs still stop at a broken file.
* A run whose final action ends holding no record, every record filtered, skipped or failed on the way to it, now warns and names that action under its summary line instead of reading as a healthy run.
* A `kind: hitl` action with several input files no longer stalls on a review nobody can see. The review page sent a shutdown 1.5s after a submit, which reached the next file's server on the same port and marked that file timed out unseen, and the tab then said "Complete" while the file after it waited out its whole timeout. Each file's page now carries its review session: a request from a page served for another file is refused (409) and changes nothing. After a submit or a timeout the tab loads the next file as soon as its server is up, and each server releases its port before the next one starts. A file whose review times out now has its records marked failed, with a warning naming the file, so the action ends completed with failures (or failed) instead of cleanly completed, and `agac retry` reopens that file's review with the decisions already made.
* An action edited after its run stopped while collecting a batch, before anything was stored, now keeps naming the edit. The batch is collected as it was sent, so every answer comes from the config before the edit, but the run that completed it stamped the edited config and later runs said nothing; now each later run names the edit until `agac run --rerun <action>`. An action edited after a stop that kept no answer is no longer told "the records it finished stand"; the warning says it kept no answers, so every record is answered under the edit.
* A tool's failure names the exception type with its message, as "Error executing UDF 'lookup': KeyError: 'no_such_namespace'", where a KeyError used to show only the key.
* A version merge no longer strands versions answered from another path. Correlation ids were minted from the workflow's absolute config path, so a version answered again from another checkout, worktree or mount (a `--rerun`, a retry, a resumed run) took other ids than the versions it kept, and the merge held each record in halves short of a version. Ids now derive from the workflow's name. Ids stored by an earlier release took the path in too: a merge meeting a record whose versions carry different ids warns, naming the records and `agac run --rerun <version base>`, which answers every version under one id.
* An action whose every record exhausted its retries now fails with the error the provider raised, not a bare count. The retry service kept the last error, but the record's error read only "Retry exhausted after N attempts" and the run's summary counted no cause for an exhausted record, so the run, `agac status` and `agac dispositions` showed "produced 0 successful records … (Found N files but failed to process any.)" and nothing more. The error now leads the record's error, the action's failure and an `on_exhausted: raise` halt, and is kept as `_recovery.retry.last_error`. An error with no message is named by its type.
* A built-in expectation now refuses a parameter of the wrong type when the rule is loaded, at preflight and at run time. A list given as a string, such as `terms: source.essay` on `contains_terms_from`, was read one character at a time, so the check passed almost any text; it now fails with a message saying params hold literal values. A string where a number is meant, and a boolean given as a number, are refused too.
* An action on a vendor that takes no key (`agac-provider`, `ollama_local`, `llamafile`) no longer needs an `api_key` at any level. Expansion asked every LLM vendor for one, so `agac inspect` and `agac run` refused such an action until a dummy key was written in, even though preflight and the run never read it. Expansion and preflight now read one rule. When a vendor that does take a key is missing one, the fix text names that vendor's own variable (for example `${OPENAI_API_KEY}`) instead of always `${ANTHROPIC_API_KEY}`.
* `agac inspect` now refuses `granularity: file` on an LLM action, as `agac run` already did, and both print the reason on the Problem line. A `granularity: file` under `defaults:` no longer marks an LLM action as File: the action runs at Record, as it always did. An action is a tool or HITL action by `kind` (including one set under `defaults:`) or by `model_vendor`, as the runtime routes it, so a `kind: tool` set under `defaults:` and a HITL action named only by `model_vendor: hitl` are now handled as those kinds throughout loading. An inherited `granularity: file` on an LLM action is reported.
* The run line now says how many of an action's records its guard skipped: `✓ repaired  4 records in 0.1s — 1 skipped by guard`. The record count already held those tombstones and gave no sign of it. `agac dispositions` shows guard skips in their own `Guard skipped` column instead of mixing them into `Unprocessed`; they are still stored as `unprocessed`, so a later run sends them again once the guard passes.
* An `llm_judge` on `model_vendor: agac-provider` now gets a verdict object back, so a judged rule can be tested offline. The judge asks in text mode for one of two JSON objects, and the mock answered every text prompt with random sentences, so every judged outcome failed with "judge response was not a verdict object". In text mode the mock now answers a prompt whose last line offers two or more JSON objects joined by `or` with one of them, chosen by its seeded generator. Any other text prompt, including one that ends with a single object, still gets prose.
* A record shipped with a failing expectations verdict no longer reads as a clean success. Under `on_exhausted: return_last` or `repair: none` such a record is still stored as a success, so nothing below is blocked and `agac retry` does not re-run it, but its disposition now carries the reason `expectations_failed`. The action line turns ⚠ and says `— N failed their checks`, the workflow line totals them (`⚠ 0.1s — 3 completed, 7 records failed their checks`), and `agac dispositions` counts them in a `Failed checks` column. The exit code is unchanged.
* A FILE tool or FILE HITL action that observes a declared seed (seed.rules) is handed it, as a RECORD tool and a guard already are. Before, the FILE scope pass never loaded the seed, so every record of the action was skipped with observe_field_missing. The seed reaches the tool's input only, never a stored row.
* `agac expect report` no longer heads an action with an unqualified `100%` when a `warn` or `info` rule failed on its records. The heading now names each non-blocking rule that failed, with failed over checked: `warned  4/4 records passed · 100%  ⚠ 1 non-blocking rule failed: never_matches_warn (warn) 4/4`. The rate, `--fail-under` and `--json` output are unchanged.
* A schema field's `minimum`, `maximum`, `minLength` and `maxLength` now reach the provider. The schema compiler copied a fixed list of keys that left them out, so no provider, real or mock, was told a field's range, although the schema file accepted them and the docs showed them. Two checks read the schema as it is sent and now hold these bounds too: a declared endpoint's reply outside `minimum` or `maximum` fails its record, and a tool action's output that breaks any of the four is refused, as one inside an array's `items` already was.
* A record that `expect:` repaired online now has one prompt trace per attempt. The trace used to pair the first prompt with the final response, so a record repaired on a later attempt showed a prompt that did not produce it, and the responses the loop discarded were lost. Each repair prompt is now stored as the next attempt beside the response it drew, and `agac traces` shows them in order.
* `schema: dispatch_task('fn')` now works in online runs: each record gets the schema its function returns, a schema definition or the name of a schema file. Every record used to fail with `Schema file 'dispatch_task('fn')' not found`. `agac inspect` refuses a function the run could not find or import.
* The mock provider (`agac-provider`) keeps a generated value inside the `minimum`/`maximum` its schema declares, and a string inside its `minLength`/`maxLength`. Its field-name rules answered first, so an integer `score` declared 1 to 4 was drawn from 1 to 100. A declared bound now wins, and the value is drawn across the bound; a one-sided bound is completed from 0, or 1000 past its edge. A field with no bound keeps the name rule.
* An action that collected no record is no longer reported as guard-filtered. With nothing collected, the guard-outcome check read 0 of 0 as "every record was a guard outcome", so the action got a node-level skip reading "All records filtered" when no guard had acted, as an action whose every record was refused can.
* `schema: dispatch_task('fn')` now works under `run_mode: batch`: each row is compiled with the schema its function returns for that record and sent with it. Batch compiled one schema for the whole action, with no record to hand the function. A batch run keeps no `add_dispatch` results, so `agac inspect` refuses `add_dispatch: true` there.
* A batch repair round's prompt trace now holds the prompt that round sent, with the validation feedback appended. It held the first prompt, without the feedback.
* A `schema: dispatch_task('fn')` is now resolved once for each record. Retries and repair rounds use the schema the record first got, online and in batch; before, the function ran again on each call and could choose another shape in the middle of a repair. Each stored record names its schema in `metadata.output_schema`.
* Retry now waits as long as a provider's `Retry-After` asks, read as `retry-after-ms`, seconds or an HTTP date, capped at `max_delay`. Before, agac parsed the header and then waited a random backoff of up to 1, 2, 4 seconds anyway. The backoff's `base_delay` and `max_delay` can now be set in a `retry:` block; before, the code read them but the schema refused them, so they were always 1 and 60 seconds.
* A first action's guard on a `source` field that no staged row holds now logs the same warning a later action's guard gets: `Action 'tag' guards on source.scroe, but no record staged from staging/rows.json holds 'scroe'.` Before, a misspelled field under `IS NULL` passed every record with no message. The run goes on, and the guard still decides.
* The preflight warning "Records may arrive at 'X' via alternate dependency ..." below a filter guard now fires only when one of the action's dependencies can deliver a record that the filter did not see. An action it only observes for context, or a dependency that runs below the filter, no longer counts as a path around it. The warning names only the dependencies that bypass the filter.
* A second `agac run` or `agac retry` of a workflow that has a run in progress now exits 1 before it loads, clears or submits anything: `Another run of workflow 'X' is in progress (pid N). Wait for it to finish or stop it, then run again.` Before, both runs did all the work, and in batch mode both submitted a batch job. The lock is a file beside the workflow's database, and the operating system releases it when the run exits or is killed. Runs of different workflows, and read-only commands, are not blocked.
* An llm_judge param (rule, model, votes, context), an expression condition, or a row_condition of the wrong type is refused at preflight and when a suite is built at run time, in the same words as the built-in checks: rule: ["be concise"] is "type 'llm_judge' takes parameter 'rule' as a string, got list ['be concise']".
* The editor no longer flags a valid schema: dispatch_task('fn') as an unresolved schema. The LSP indexer tells a dispatch call from a schema file name with schema_dispatch_function, the test agac inspect and agac run use.
* agac dispositions --quarantined, its action-level table and the agac expect report per-rule table print whole on a narrow terminal, as the dispositions summary does, so a record ID, action name, rule id or type is no longer cut short with an ellipsis.
* A warning that an action below the first reads a source field no staged row holds prints once per staged file per run, not twice. The walk's pre-check logs it; the processing pass runs the same check without logging.
* agac retry --filter takes the workflow's run lock, as agac run and agac retry do, and exits 1 while a run or retry of the workflow is in progress. It rewrites dispositions, stored rows, the status file and the retry manifest, so a run in progress could undo it. A dry run still reads past the lock.
* agac clean (in every mode, whenever it finds something to remove) and the skills' reset_workflow.py --full take the workflow's run lock before they ask or delete anything, with or without a store folder, and exit 1 while a run or retry is in progress, removing nothing. They hold it until they finish, so a run started while clean waits at its prompt is refused. They never delete the lock file: clean --all leaves the store folder holding only the empty lock file. Before, clean --all deleted the store folder with the lock file in it, so a second run then passed the lock check.
