## 1.1.0 - 2026-09-13
### Enhancement or New Feature
* A workflow run now prints as a progress stream instead of a log: one line per action, grouped under the dependency step that produced it, with its record count, duration and model. Framework bookkeeping no longer interleaves with it, and the step structure is written to `events.json` for the first time — previously it existed only on the terminal, and was printed twice there. The post-run summary table is removed: it re-rendered every action the stream had already shown, so a run ended four separate times. Output for the bundled example workflow went from 127 lines to 58.
* Framework-internal log messages are kept off the console without being lost. Events carry a `diagnostic` flag: the terminal drops them unless the run is verbose, while the JSON log files keep them at full severity. The rule for what counts as internal is written down — whether the person running the workflow can change what the message describes — so classification is reviewable rather than a matter of taste.
* `AGAC_MAX_RECORDS` caps every action's record count for a run, regardless of what the project config asks for. A capped run says so, because a truncated run that stays silent looks like a complete one. An unusable value fails the run rather than being ignored.
### Under the Hood
* Release v1.0.0 — batch changie entries, bump version
* Faster project scans: the docs scanner no longer walks the project twice per workflow, each workflow event log is read once instead of twice, project-tree searches skip virtualenvs and VCS directories, and the schema-tree walk is reused across `load_schema` calls.
* Removed a superseded source resolver and two paths traced as unreachable, keeping the two that were load-bearing defensive guards — deleting those would have replaced a loud failure with a silent one.
* The lockfile is back in step with `pyproject.toml`; `uv lock --check` had been failing. Metadata only — no resolved dependency version changed.
### Bug Fix
* A failing record was reported twice on the console — once by the processing strategy, once by the result collector — and the action's own failure line described file processing rather than the fault, because the record's cause was flattened into a string two layers below. The collector is now the single reporter for both online and batch runs, and the cause travels intact to the action line, where it leads the message so it survives the 60-character truncation `agac dispositions` applies.
* Every version-merge consumer reported zero records while its output was on disk. The per-run record count is a delta measured across the action, and the correlated input is written into the consuming action's own target before it runs, so the snapshot already included it. Both run paths now measure from before input resolution.
