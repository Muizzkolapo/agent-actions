- When a tool action has a context_scope block, it switches to explicit field control mode where only specified fields are available; passthrough is required to preserve fields from upstream actions that the tool
  doesn't process but downstream actions need, preventing those fields from being lost when the tool returns its output.

- WHen using workflows referencing (Jinja2 rendering), field references use {{ reference.field }} syntax where reference must be one of the namespaced contexts (source for input data, agent_name for previous agent outputs, seed for
  static file data, loop for loop context, or workflow for metadata) - plain {{ field }} without a reference prefix is NOT supported because prompt_context is a namespaced dictionary structure.

-   The dispatch_task('handle_quiz_type') call in a prompt template is processed after Jinja2 field rendering where it extracts the function name, calls the Python function with llm_context as a JSON string
  argument, receives a dynamically selected prompt template based on the quiz_type field value (UNDERSTANDING/APPLICATION/IMPLEMENTATION/ANALYSIS), and replaces the entire dispatch_task() call with the
  returned template string before sending the final prompt to the LLM.
