01

Problem Statement

The framework's record bus conflates identity-of-origin with action-output payload: the user's original staging fields are stuffed into record["content"]["source"] as if "source" were just another action namespace. Consumers must duck-type their way back out — and on the phase-5-record-state-machine branch the duck-type now misclassifies wrapped target envelopes, breaking the source.<field> reference for every action after the first. The bug surfaces as context_scope.observe field 'source.page_content' not found at runtime; the underlying disease is that source has no first-class home on the record envelope.

Where the Pain Lives

Bus boundary: agent_actions/prompt/context/scope_builder.py:_load_source_namespace branches on "content" in source_content as a shape probe. Same naive probe in agent_actions/prompt/context/scope_namespace.py:_extract_content_data and in agent_actions/prompt/context/scope_application.py:_resolve_source_content. First-stage synthesis lives in agent_actions/processing/record_helpers.py:extract_existing_content, where raw fields get wrapped under {"source": raw} and merged into content by RecordEnvelope.build. Three places, three sources of truth, drift guaranteed.

Why Now

PR #433 (record state machine) appended _state and _transitions to every stored record. The new keys make the duck-type misclassify wrapped target envelopes more often, and the additive-content shape was simultaneously regularised through RecordEnvelope.build — so both halves of the assumption that kept the duck-type correct broke at the same time. Pipelines with two or more actions are unrunnable on this branch.

Cost of Inaction

Every multi-action pipeline crashes at action 2 with the missing-source error. The state-machine branch is unmergeable. Patching _load_source_namespace alone re-leaves source inside content — symptom fix, root cause intact, next change to the data shape will re-break it. A user with hundreds of dollars of LLM spend in a stored DB cannot read their data with new code.

02

Success Criteria

  • Single source of truth. Every record carries source at exactly one location: top-level on the envelope. No code path ever reads it from content["source"].
  • Bus reads source in O(1). _load_source_namespace contains zero shape branching: field_context["source"] = record.get("source", {}).
  • Multi-action pipelines work. A two-action pipeline where action 2 observes source.page_content resolves correctly when (a) source_relative_path is configured, (b) it is missing, (c) the upstream is guard-skipped, (d) the upstream is a 1→N version expansion. All four scenarios covered by tests that fail today and pass after.
  • Source survives every state transition. Guard-skipped, cascade-skipped, exhausted, and failed records all retain their source field — proven by tests.
  • Source-data table shape is preserved. Records persisted to the source_data SQLite table remain flat (they are the source); no double-wrap on save or load. Verified by round-trip test.
  • Net code reduction. Two helper functions deleted (_resolve_source_content, _build_source_index, _enrich_source_namespace), one helper collapses (extract_existing_content), one branch deleted in PassthroughTransformer.transform_with_passthrough.
  • Lint, typecheck, full test suite green.

Constraints & Trade-offs

Codebase Constraints

Must follow Agent Manifest Protocol: every module touched must have its _MANIFEST.md updated for any change to the ## Modules, ## Project Surface, or ## Dependencies tables. Logging convention is logger not print. Lint is ruff; tests are pytest (no new test framework). No new third-party dependencies.

Dependency Constraints

The envelope is a pure data structure with no IO. Carry-forward of source through _carry_tracking_fields requires only a one-line add to RECORD_TRACKING_FIELDS; this also extends RECORD_FRAMEWORK_FIELDS automatically (it's the union with stage fields), which already feeds metadata-exclusion logic. The hoist must coexist with the existing batch text-chunk row shape ({content: "<str>", batch_id, batch_uuid, …}): content is already a framework field so it stays put, but batch_id / batch_uuid are not in the framework set today and would otherwise be hoisted into source. We extend the framework set or carve them out at admission — see Decision 4.

Key Design Decisions

Decision 1 — Where source lives

Chosen: top-level field on the envelope, alongside source_guid, _state, content.

Alternatives considered: (a) keep nested in content (status quo, with naive duck-type fix); (b) separate "metadata" sub-dict on the envelope; (c) external sidecar table keyed by source_guid.

Rationale: source is identity-of-origin — same conceptual class as source_guid, which is already an envelope tracking field. Treating it as a tracking field unifies the carry-forward logic, eliminates duck-typing, and makes the bus a one-liner. A sidecar table would add IO to every prompt build for no behavioral gain. A metadata sub-dict adds a level of indirection without justification.

Decision 2 — Source carry mechanism

Chosen: add "source" to RECORD_TRACKING_FIELDS; _carry_tracking_fields already handles propagation through RecordEnvelope.build(), build_skipped(), and downstream helpers.

Alternatives considered: explicit build(source=…) parameter on the envelope API.

Rationale: source is set once at staging admission and never mutated by actions. That is precisely the contract RECORD_TRACKING_FIELDS encodes. Reusing the existing mechanism is one line of code; introducing a new API surface is many.

Decision 3 — Source data table shape

Chosen: source-data table records remain flat — they are the source.

Alternatives considered: (a) save full envelope shape ({source: {raw}, source_guid, …}) to source-data table for consistency with target_data table.

Rationale: target_data records carry source because they need to reference origin while themselves being something else (action output). Source-data records are origin — wrapping their own raw data under "source" would create a circular shape (row["source"]["source"]["source"]…) and force every reader to un-wrap. The flat shape stays canonical; only target records gain the envelope field.

Decision 4 — Admission hoist boundary

Chosen: RecordEnvelope.admit_staging_row hoists every key NOT in RECORD_FRAMEWORK_FIELDS into record["source"]. Add batch_id and batch_uuid to the framework set so they don't get mistakenly hoisted.

Alternatives considered: maintain a separate "do not hoist" allowlist; hoist only "user-looking" keys via heuristic.

Rationale: RECORD_FRAMEWORK_FIELDS is already the canonical enumeration of "framework metadata, not user data." Extending it for batch_id / batch_uuid closes a real gap — those keys are framework-managed, not user-supplied. Heuristics fail in surprising ways at scale.

Decision 5 — Source-data save path

Chosen: _save_source_data persists pre-admission snapshots. For paths that today alias src_text = data_chunk (CSV/XLSX/XML), take a shallow copy before _admit_staging_rows mutates. For batch paths (where src_text = []), introduce _to_source_table_row(row) that emits the flat shape from a hoisted row.

Alternatives considered: (a) make admission non-destructive (return a new dict); (b) save first then admit; (c) double-mutate the saved row to un-hoist after save.

Rationale: pre-admission snapshots match the existing intent and are local to initial_pipeline.py. Non-destructive admission would require re-binding lists everywhere admission is called — wider surface. Save-first-then-admit reorders a load-bearing sequence used by the rest of staging.

Decision 6 — File mode tool input

Chosen: pipeline_file_mode.extract_tool_input includes record["source"] as a synthetic "source" namespace in the tool's flattened input, replicating the pre-refactor shape that tools observed under source.field.

Alternatives considered: tools learn about envelope source separately and read source.field through a different path.

Rationale: tool API stability. Tools already expect a flat dict with source alongside upstream namespaces; preserving that shape avoids breaking every tool in the wild for a refactor that's about plumbing.

Decision 7 — No backward compatibility

Chosen: hard cutover. Records produced by old code cannot be read by new code, and vice versa. No feature flag, no shim, no migration.

Alternatives considered: dual-read shim for one release; runtime migration of stored records on first read.

Rationale: the change is on an unmerged branch (phase-5-record-state-machine) with no production deployment. The user explicitly opted out of compatibility. Compat code would be tech debt deleted in the next release anyway.

Solution Design

High-Level Architecture

Today's record is a wrapper around content; identity-of-origin lives inside content as a pseudo-namespace; framework metadata (_state, _transitions, source_guid) lives at top level. The conflation between "user data" and "namespaced action output" inside content is the architectural error.

The new envelope is a flat record with a clean separation of concerns:

record = {
    # Tracking fields — stable identity, set once, carried verbatim
    "source_guid": str,
    "source": {raw user fields},        # NEW — was nested in content
    "version_correlation_id": str | None,

    # Stage fields — rebuilt per stage, framework-managed
    "target_id": str,
    "node_id": str,
    "lineage": [...],
    "metadata": {...},
    "content": {                        # ONLY action namespaces now
        "action_1": {...},
        "action_2": {...},
    },
    "_state": "active",
    "_transitions": [...],
    "_recovery": {...},
    "parent_target_id": str | None,
    "root_target_id": str,
    "chunk_info": {...},
}

The bus reads source from a fixed location. RecordEnvelope.build() propagates it via the existing tracking-field carry. extract_existing_content stops synthesising it. _resolve_source_content's entire mechanism — looking up source by source_guid in a list, building an index, returning the wrapped record's content field — disappears.

Data-flow diagrams

Before — three places to look, two of them wrong:

[STAGING FILE] {page_content, title} │ │ admit_staging_row(): stamps _state only ▼ [STAGE ROW] {page_content, title, source_guid, target_id, _state} │ │ action_1: extract_existing_content(is_first_stage=True) │ wraps raw fields as {"source": raw} into content ▼ [ACTION 1 OUTPUT] {content: {source: {raw}, action_1: {…}}, _state, _transitions, source_guid, target_id} │ │ action_2: source_data lookup returns the WHOLE envelope │ _load_source_namespace sees "content" key → unwraps: │ field_context.source = {source: {raw}, action_1: {…}} ← WRONG ▼ [ACTION 2 INPUT] source.page_content → KeyError

After — one place, no probing:

[STAGING FILE] {page_content, title} │ │ admit_staging_row(): │ • hoist non-framework fields → record["source"] │ • initialise content = {} if absent │ • stamp _state ▼ [STAGE ROW] {source: {page_content, title}, content: {}, _state, source_guid, target_id} │ │ action_1: RecordEnvelope.build() │ carries source via _carry_tracking_fields() ▼ [ACTION 1 OUTPUT] {source: {page_content, title}, ← unchanged content: {action_1: {…}}, ← only namespaces _state, _transitions, source_guid, target_id} │ │ action_N: bus reads record["source"]. No lookup. No probe. ▼ [ACTION N INPUT] field_context.source = record["source"] source.page_content → "..." ✓

Interface Contracts

  • Envelope invariant: after admit_staging_row() or any RecordEnvelope.build*() call, the returned record has "source" at top level (possibly empty dict) and "content" at top level. Neither key contains the other. Other framework keys (_state, source_guid, target_id, …) live alongside, never inside content.
  • Source mutability: record["source"] is set exactly once at staging admission. Actions never write to it. Helper code that builds tombstones, skipped records, or exhausted records inherits source via the tracking-field carry.
  • Bus contract: build_field_context_with_history(current_item=…) derives the source namespace from current_item.get("source", {}). The source_content parameter is removed (callers no longer pass it).
  • Source-data table shape: rows in the source_data SQLite table are flat — they are the canonical raw input. They carry source_guid for cross-record lookup but no source field. Loaded as list[dict[str, Any]] via SourceDataLoader.load_source_data.
  • File-mode tool input: extract_tool_input(record, context_scope) emits a flat dict with "source" drawn from record["source"] when source.* is observed; this matches the pre-refactor flat-keys API.

Failure Modes & Recovery

  • F1. Admission called twice on the same row → second call is a no-op (idempotency contract): if "source" already present at top-level, do not re-hoist non-framework keys. Recovery: guard with if "source" not in record: ….
  • F2. Staging row with both top-level "source" and other raw fields (user data has a literal "source" key) → ambiguity. Recovery: treat literal user "source" as raw data and hoist alongside other raw fields: {user_source: …, page_content: …} becomes {source: {source: user_source, page_content: …}}. Documented behavior in tests.
  • F3. Old DB record without top-level source read by new code → field_context["source"] = {}; templates/guards referencing source.field raise the existing missing-field error with a clear message. Acceptable per Decision 7.
  • F4. Tool input lacking source namespace because tool config doesn't observe source.* → extract_tool_input only injects source when explicitly observed (matches today's behavior for other namespaces).
  • F5. Batch text-chunk row (where content is a string not a dict) → admission preserves content as framework-protected; raw-field hoist skips (nothing else outside framework set in those rows). Verified by test.

Observability Strategy

Add a logger.debug at admit_staging_row reporting the count of fields hoisted. Add a logger.warning at _load_source_namespace if a record passes through with no "source" key (signals staging admission was skipped — a regression we want to spot fast). The existing ContextNamespaceLoadedEvent at scope_builder.py:98-105 already fires when source is loaded; no new event needed.

Testing Strategy

  • Unit (envelope): assert "source" in RECORD_TRACKING_FIELDS; RecordEnvelope.build carries source from input to output; build_skipped carries source; admit_staging_row hoists non-framework keys; admit_staging_row is idempotent.
  • Unit (bus): _load_source_namespace reads current_item["source"]; returns empty when source absent; build_field_context_with_history still produces field_context["source"] for downstream actions.
  • Integration (regression for the reported bug): two-action pipeline, action 2 observes source.page_content, executes correctly when: (a) source_relative_path is set; (b) source_relative_path is None / DB read fails; (c) action 1 was guard-skipped; (d) action 1 was a 1→N expansion.
  • Integration (round-trip): staging row written to source_data table, read back, asserts shape is flat (no nested source.source).
  • Integration (file-mode tool): tool action observes source.*, receives source fields in its flattened input.
  • Lint: ruff check . clean.
  • Full suite: pytest green.

Scaling & Evolution

Growth Projections & Limits

Source size scales with input row size; same constraint as today (raw fields used to live in content instead of top-level). No new memory cost — moving keys, not duplicating. The _carry_tracking_fields path is already O(|TRACKING_FIELDS|) per record — adding one entry doesn't change the asymptote.

Future Extension Points

If we ever need additional identity-of-origin fields (e.g., source ingestion timestamp, source file checksum), they can be added as new envelope tracking fields without touching the bus or any consumer. The carry-forward mechanism scales naturally. Before this refactor, adding a new origin field meant either jamming it into content["source"] (which forced every consumer to re-special-case it) or adding ad-hoc top-level fields without carry semantics.

Deprecation Considerations

The extract_existing_content function with its is_first_stage kwarg becomes a thin alias for get_existing_content; we may inline it at call sites in a follow-up PR after one release cycle, but that's cosmetic. The _enrich_source_namespace helper and its tests are deleted outright. The _resolve_source_content / _build_source_index pair is deleted outright. No long-lived deprecation surface.
